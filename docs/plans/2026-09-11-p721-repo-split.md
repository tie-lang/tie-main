**库存放原则** / Placement principles：
- 组件仓 = 「一组件一仓」：源码 + 该组件的文档/脚本/测试/示例自洽成仓，独立发行自己的版本。
- 主仓 = 聚合/发行仓：只保留「面向用户"整套工具链"」的入口（发行物、当前版本文档、组件导航）。
- 依赖「下游不反向依赖上游」：tiec 是根基仓，tink/tsp/trm/tiu 等驻各自仓独立演进，主仓仅在聚合发行时引用各仓版本。

## 3. tie-main 保留 vs 迁出边界 / Keep-vs-Move Boundary

**保留在 tie-main**（聚合/发行仓目标态）：
- `dist/`：发行物目录（zip 出仓，不跟踪进 git；p.7.2.4 起含 `src/` 收拢布局 + `-src.zip`）
- `docs/`：当前版本文档（language/ai-guide/release/cli/tiec/tie-script/prompt-pack/designs/plans/superpowers 等）
- 仓库级文件：`README.md`、`CHANGELOG.md`、`NEW.md`、`LICENSE`、`CONTRIBUTING.md`、`ROAD.md`、`AGENTS.md`、`.gitignore`、`.gitattributes`、`.github/`（CI 聚合）、`assets/`（logo 等宣传资源）
- `docs/plans/`：后续开发模块规划（p.7.2/p.7.3 等规划文档按惯例随主仓演进，实施后归档）

**迁往组件仓（清单 + 顺序，本轮不执行）**：
- 第一批（根基，随 `tiec` 仓）：`compiler/`、`prep/`、`std/`、`ext/`、`rdu/`、`repl/`、`scripts/`、`tests/`、`examples/`
- 第二批（工具，各自仓）：`pkg/` → tie-pkg；`compiler/lsp/` → tsp；`tieDB/` → tiedb；`sys/`、`tools/` → 归并相关组件仓或归档
- 第三批（附属，各自仓）：`skills/tie-dev/` → tie-dev；`editor/vscode-tie/` → vscode-tie
- 说明：`target/`、`third_party/`、`archive/`、`diagdocs/`、`.codegraph/`、`.omo/`、`.superpowers/` 为构建/内部资源，随宿主组件仓定位（不单独成仓）

> EN (keep vs move): tie-main keeps `dist/`, current-version `docs/`, and the
> repo-level files (README/CHANGELOG/LICENSE/NEW/CONTRIBUTING/ROAD/AGENTS,
> `.github/`, `assets/`). The migration list (batch 1: compiler core + std/ext/rdu
> + repl + scripts + tests + examples → `tiec`; batch 2: pkg → tie-pkg, lsp → tsp,
> tieDB → tiedb; batch 3: skills → tie-dev, editor → vscode-tie) is **planned
> only — no moves in this round**.

## 4. 迁移清单（可执行）/ Migration Checklist (actionable)

迁移本身的执行**不在本子项内**；本清单在后续以「每个组件仓一次迁移 = 一个任务」方式执行
（真实建仓/推送由主代理/用户按确认流程执行）：

1. 建组件仓骨架：`git init -b main` + `LICENSE`（TPL 2.0 标准全文）+ `README`（## License）+ `.gitignore`；gh 建仓（tie-lang org，public，TPL 2.0）
2. 以 `git filter-repo`/`git subtree split` 保留历史导出，或新仓冷启动 + 首版本快照（组件仓是否带历史：按主代理决策，默认新仓冷启动）
3. 组件仓自恰化：补齐该组件的 `docs/`（组件 README + 发行说明模板，见 p.7.2.2）、`scripts/`（该组件打包入口）、`tests/`（组件层探针）
4. 主仓摘除：删除对应目录 + `.gitignore` 同步 + README/ROAD 组件索引更新（引用指向新仓）
5. 后续任务已就位的对接点：p.7.2.3 聚合校验（`scripts/tie-versions.data.tie` 引用组件版本约束）、p.7.2.5 registry（组件包经 `tie pkg publish` 入库）

**顺序建议** / Suggested order：`tiec`（根基，先于一切）→ `tink` → `tsp` → `tie-pkg` → `tiedb` → `tiu` → `trm` → `tiwi` → `vscode-tie` → `tie-dev`。
