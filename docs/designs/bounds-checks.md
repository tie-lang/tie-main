# 运行期边界检查：越界读、负下标、除零 / Runtime bounds checks

> 状态：**已落地**（2026-10-06）。开关：**默认开**，显式 `-l2`/`-l3` 关，`--check-bounds` 强制开。
> 相关提交（tiec）：`b578713`（表越界）· `fa2f07a`（负下标）· `686d5a5`（单分支优化 + 编译器越界点修复）· `40a9977`（除零）· `b4740da`（分档）。

## 1. 冲突 / The conflict

规范 §3.15 规定「下标越界在运行期报错」，实现一直返回元素零值。把这条落实，会与项目的
**「性能永远优先」**直接冲突：一次边界检查要给所有表读写加税。

按「**先做检查 → 用它清掉全部依赖点 → 再定档**」的顺序推进，先拿到了事实，再定取舍。

## 2. 三项检查 / The three checks

| 检查 | 判据 | 无检查时的实际行为 |
| --- | --- | --- |
| 表**高侧**越界读 | `tbl_at` 的 ok 出参 | 返回元素零值（`table<string>` 曾返回**空指针** ⇒ 段错误）|
| 表**负下标**读 | 需**单独**判 `iv < 0` | **堆下读**：`t[-1]` 返回分配器元数据 |
| **除零**（`/ % \ %%`）| 除数 `== 0` | **进程挂死**（rc=124 超时，非崩溃非错值）|

### 2.1 负下标：`ok` 标志**结构上**覆盖不到它

`tbl_at` 的判据是 `if i < len` —— 对**负数恒真**（`-1 < 2`），于是执行
`memcpy(data + (-1)*esz)`，而且 `ok` 报 **1**。这不是「忘了接线」，是「判据不含负边界」。

实测（**开关关着**、**完全没写 unsafe**）：

```tie
var t: table<i64> = table_new_i64()
table_push(t, 111)
table_push(t, 222)
var neg: i64 = 0 - 1
println(to_string(t[neg]))     // -8070398854950596583 ← 分配器元数据
```

两次运行值不同 ⇒ 读的是表头前的分配器元数据。这是「不用 `unsafe` 就无需担心内存安全」
这条承诺上的**唯一一个洞**。★ **写**路径早有此检查（诊断「表下标越界（负索引）」），
**读**路径没有 —— 同一洞在两条路径上的不对称是它长期未被发现的原因。

### 2.2 检查必须划在**用户源码的读点**，不能划在运行时入口

运行时的**尾下标钳制/弹出**用 `len>0 ? len-1 : 0`，**故意**让空表走越界分支，并依赖
`ok=0` 才跳过 `set_len`。在 `tbl_at` 处报错会把合法的 `pop`/`last` 打死。
⇒ 检查只作用于编译器发射**用户源码 `t[i]`** 的位置（`tig_index_read`）。

### 2.3 除零不是陷阱，是**挂死**

x86 的 `sdiv`/`srem` 遇除数为 0 会触发硬件异常，而这里实测的行为是**进程既不返回也不退出**
（`10 / 0` rc=124；`10 / 2` 正常打印 5）。比崩溃更难排查。
**浮点不检查**：`1.0 / 0.0` 得 `inf`/`nan` 是 IEEE 754 定义行为，大量程序依赖它。

## 3. 成本 / Cost

三项检查的**增量**都很小，因为判据大多**本来就算好了**：

* 表越界的判据（`i < len`）由 `tbl_at` 内部算出并经 ok 出参返回，而唯一的发射点
  把 ok 存进 `ok_addr` 后**从不读取**（死代码）。加检查的增量 = 1 次 i8 load + 1 次 icmp
  + 1 个几乎不跳的分支。
* 负下标 = 同一 panic 块上的**一个 icmp**。
* 两项条件可合成**一个分支**：`bad = (ok == 0) | (iv < 0)`。原先两个条件块 + 两个分支，
  合成后少一个基本块、少一次分支 —— 这一项把总代价从 **+9.6% 降到 +2.1%**。

### 实测（交替 6 轮自编译）

| 配置 | 耗时 |
| --- | --- |
| 检查全关 | 34475 ms |
| 三项检查全开 | 34807 ms |
| **净代价** | **+0.9%** |

`-l2` 下产物与接线前**逐字节相同**（用新旧编译器编译同一输入 `cmp` 验证）。

## 4. 分档 / Tiering

```
不带优化档           检查开    开发期（默认）
-l2 / -l3           检查关    发布（自举与发布都用这档）
--check-bounds      检查开    显式覆盖二者
```

即 C/C++/Rust 的 **debug_assert / release** 模型。
判据用的是**显式** `-l2`（`g_llvm_set`），不是有效档位 —— 因为 l2 **本来就是默认档**，
按档位判定会让每次构建都变成发布构建。

## 5. 审计抓到的「依赖越界读」点 / What the audit found

检查一旦落地，就能用来**扫全树**。做法：用带检查的编译器**编译编译器自身**
（覆盖面最大），并开 `TIE_CB_AUDIT=1`（只报告不中断，一次收全）。

| 位置 | 形态 | 为何「恰好对」 |
| --- | --- | --- |
| tiu `layout.tie` `g_reflow[n]` ×2 | 表只沿**被标记的祖先链**增长，却按 **DFS 全序**读 | 返回 0 与「未标记」语义相同 |
| tiec `irgen_agg_p1` `g_cmp_getter/setter[id]` ×5 | 无计算属性的模块上该表**为空** | 读到 0 与哨兵 −1 都落到「独立探测」分支 |
| tiec `irgen_stmt_p3` `collect_other_writes` `s_tags[-1]` ×76 | `child()` 缺子节点时给 **−1** | 垃圾值**恰不等于 6** 才正确 —— 而 6 正是它要比较的 tag |

最后一例最危险：`s_names[wbase]` 会把垃圾节点 id 当成写目标登记，
唯一的屏障是「已释放内存里的内容不等于 6」。

**修法**：显式范围守卫（`>= 0 && < len`）或**重置时一次补齐**（`ensure_len(t, total()-1)`）。
三处修完行为**逐字不变**。
