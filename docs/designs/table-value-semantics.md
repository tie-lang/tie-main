# 表默认值语义：实施方案（2026-10-04 定案）

*EN: Table value semantics — implementation plan (2026-10-04)*

> **背景**：现方案（越界写按 rc 分流 + `deep` 无条件克隆 + 闲置的 COW）是**同一个不变量
> 坏掉之后的三个各自绕行**。不变量 = 「句柄 @40 的 rc 代表有几个别名」，而它在
> struct 按值拷贝下不成立（不 retain 表字段）。评估见
> `tiec/_spec_audit/z/table_semantics_eval.md`。
>
> **裁决原则（用户）**：**不使用 unsafe 时，无心智压力，不用担心内存安全问题。**
> ⇒ 安全路径必须**默认就对**：不需记修饰符、不需推理别名、不需担心运行时中止。
>
> **目标模型**：**默认值语义（COW 支撑）** + **`shared` 显式共享**（高性能、不用 unsafe）
> + **`deep` 显式深拷贝**。三者在「复制 ↔ 共享」轴上的位置：
>
> | 修饰 | 语义 | 代价 | 用途 |
> | --- | --- | --- | --- |
> | （默认） | 值语义（写时分离） | 独占时零成本；共享+写时一次 O(n) | 绝大多数代码 |
> | `shared` | 显式共享，就地改 | 零拷贝 | 需要共享累积的高频路径 |
> | `deep` | 入口深拷贝 | 每次调用 O(n) | 需要完全独立的边界 |

---

## 0. 现状（实测，提交 `f2778eb`）

* **`shared` 关键字已落地**（r.1.6.12）：parser 识别、bit5 登记、`shared × deep` 互斥诊断（E00905）、
  重复修饰诊断已含 deep/shared。**今天是 no-op**（默认即共享）——它的价值是**为迁移提供落点**。
* 不变量仍不成立：retain 判据一律是 `types.is_table(表达式类型)`，**从不递归聚合**
  ⇒ struct 拷贝 / 数组 / `/map` 里的表元素都不 retain。
* `tbl_cow` / `tbl_set_cow` / `tbl_push_cow` **零调用**。
* `deep` 用**无条件克隆**（`tl_tbl$tbl_clone`），因为 rc 不可信。
  ⚠ `irgen_p2.tie:665` 的注释「rc>1 才克隆，rc=1 零成本」是**过时描述**，实际不是这样。
* 越界写按 rc 分流（`rc==1` 扩容 / `rc>1` 诊断退出）；**高侧越界读返回 0**（与规范 §3 冲突，待裁决）。

## 1. 爆炸半径（实测）

| 范围 | 依赖「隐式共享」的写点 | 涉及函数 |
| --- | --- | --- |
| tiec 自身 | ≈104 | 33 |
| tlib | ≈374 | 122 |
| **合计** | **≈480** | **155** |

判据：`var x = <某表>` / 形参传入后对 `x` 做写操作（`table_push` / `x[i]=` / `table_pop`），
且之后使用原表。⇒ 这些点在默认转向值语义后**行为会变**（累积丢失），需逐个判定
「本意是共享 ⇒ 标 `shared`」还是「本意是本地副本 ⇒ 保持默认」。

### 阶段 2 — 修复 rc 不变量（**最难，也最关键**）

**精确点位（2026-10-04 侦察，提交 `f2778eb` 时点）**

| 类别 | 位置 | 现状 | 要做 |
| --- | --- | --- | --- |
| 判据 | `irgen_stmt_gen_p1.tie:179` | `types.is_table(iv4)` —— **只看一层** | 换 `type_has_table_field(ty)` **递归**判据 |
| 聚合拷贝 | `irgen_agg_p3.tie` 的 struct 拷贝 / `tig_struct_construct` | 只发整聚合 load+store，**无逐字段 retain** | 拷贝后按字段 GEP + retain |
| 聚合构造 | 同上 | 同 | ⚠ 同一条「瞬态值免 retain」规则必须沿用（见下） |
| 析构 | `irgen_stmt_p1.tie:257` `tig_tbl_exit_release` | 只 load/release `g_tblcand_allocas`（**表/map 直接局部**） | 增并行的「聚合候选」表（槽 + 类型），出口按字段 GEP + release |
| 循环回边 | `irgen_stmt_p1.tie:276` `tig_loopvar_release` | 同 | 同上（否则循环内聚合的字段不释放） |
| 容器元素 | `irgen_agg_p3.tie:511`（**已修重复**，见提交 `b4acf9d`） | 别名元素 retain 一次 | 递归：元素若为聚合，其表字段亦需 retain |

**必须沿用的既有规则（漏了就会泄漏）**：`s_tags[init] != 7 && != 12`
—— **调用（tag 7）与表字面量（tag 12）是瞬态值**，所有权直接转移给目标槽，**不 retain**。
聚合路径同理：`var s = S(table_new_i64())` 构造出的表是瞬态的，**不能 retain**
（否则出口 release 只 -1，净剩 1 ⇒ 泄漏）。判据要区分「拷贝既有别名」与「构造新鲜值」。

**已完成的先决清理**：
* `b4acf9d` 去掉 `rp_decl` 里**逐字重复两遍**的 retain 块（`57d09a6` 搬运函数据致）
  ⇒ 行池别名元素 rc 多计 1、永不释放。修复后内存峰值 8.8 → 8.6 MB。
* 待清：`irgen_p2.tie:665` 注释「deep 按 rc>1 才克隆」**过时**（实际无条件克隆），
  与 `irgen_str_p2.tie:76` 的说明互斥 —— 统一措辞。


让「聚合值拷贝」逐字段 retain/release，使 `rc == 别名数` 成立。

**要做**：
1. **拷贝侧 retain**：`irgen_agg_p3.tie` 的 struct 拷贝 / `tig_struct_construct`、
   以及数组/元组/map 里含表元素的情形 —— 按**类型递归**枚举表字段并逐个 retain。
   现在只有一层的 `types.is_table(表达式类型)`，需换成 `type_has_table_field(ty)` 递归判据。
2. **析构侧 release**：聚合局部变量出作用域时，逐表字段 release。
   现析构只覆盖表/map 直接局部（`irgen_stmt_p1.tie:257/276`），需扩展到聚合。
3. **传参/返回**：与 1、2 同源——凡「复制一个聚合值」的地方都要成对。

**关键设计问题**（必须先定，否则泄漏）：
* 值拷贝会**增殖副本**：只 retain 不 release ⇒ 泄漏（表永不释放）；
  只 release 不 retain ⇒ 双重释放。**必须成对**，且每处拷贝都要有对应的析构点。
* **局部聚合**：无逃逸时可省掉 retain/release 对（编译器可证「拷贝只在本函数内存活」）——
  但那是优化，**不是正确性前提**：正确性靠成对。
* **已知坑（侦察发现）**：
  * `irgen_agg_p3.tie:509-522` 的 retain 块**重复两遍**（先清理）
  * `irgen_p2.tie:665` 注释与 `irgen_str_p2.tie:76` 注释**互斥**（先统一）

**风险**：修准 rc 会让越界写门禁**变严**（struct 副本别名从「不可见」变「rc>1 ⇒ 中止」）。
若不接阶段 3，等于把「静默改形状」换成「运行时中止」——**都不是值语义**。
⇒ **阶段 2 与阶段 3 必须同批交付**，否则中间态比现状更差。

### 阶段 2 — 进度（2026-10-04，三个提交）

阶段 2 的**核心已落地并过门禁**（tiec `b4acf9d` / `f36a434` / `ead42da`）：

| 提交 | 内容 |
| --- | --- |
| `b4acf9d` | 去掉 `rp_decl` 里**逐字重复两遍**的 retain 块（`57d09a6` 搬运函数据致）——行长池别名元素 rc 多计 1、永不释放 |
| `f36a434` | **绑定处 retain + 出口 release**（`tig_agg_retain_bound` / `tig_agg_release_fields` / `ty_has_table`，含独立的 `g_aggcand_*` 候选表） |
| `ead42da` | **回边 release**（`tig_agg_loopvar_release` / `tig_agg_release_guarded`，零值哨兵 + select，不分裂块） |

**效果（实测）**

* **rc 现已计入 struct 字段别名**——`var t = table_new_i64(); var s = S(t); s.t[5]=7`
  从「静默扩容」变为**正确中止**（rc=2）；而 `S(table_new_i64())`（瞬态实参）仍照旧扩容。
* **内存峰值 40.6 MB → 8.9 MB（4.6×）**（循环内每轮绑定并丢弃一个含表字段的 struct）。
  回边释放是其中最大的一块（38.1 → 8.9），因为它修的正是「逐轮 +1 无界增长」。
* 回归 **210/11 FAIL 集合未变**、三阶不动点、零警告；三个编译器产出的程序均 exit 0（**无双释放**）。

**设计要点（实现时定的，别丢）**

* **retain 打在绑定处，不打在构造处**——`f(S(a))` 的临时 struct 没有本地槽可释放，
  在构造处 retain 会**无人 release ⇒ 泄漏**。绑定处才与出口 release 成对。
* **形参槽不登记不 retain**——沿用「表实参是借用」的既有约定（callee 不拥有、不释放 ⇒ 也不 retain）。
* **瞬态判据逐字段判**——构造调用的实参若是调用/字面量（tag 7/12）⇒ 所有权已转移 ⇒ 不 retain。

**已知副作用（保守方向，需知情）**

* 槽在循环结束后**仍持有句柄**，直到函数出口才释放 ⇒ 该窗口内 rc 多 1。
  故「循环后对 struct 字段做越界写」比改动前**更保守**（会中止而非扩容）。
  方向安全（宁中止不放行），且阶段 3 接入 COW 后越界写变为「分离后扩容」，此副作用自然消解。

**★ 关键字变更的连锁教训**

`shared` 成为硬关键字后，**13 个 tlib 模块 + 3 个 tiec 测试**因把 `shared` 当标识符而坏
（`std/x25519.tie` 一坏就带倒 tls → http/httpc/ws/sse/tink 四件套）。
**首次扫描被 `head -5` 截断**所以漏了。
⇒ 纪律：**保留一个词之后，必须对全部仓库做完整扫描（不加 head）**。
修完后 tlib 编译面 **118 → 131**，与「关键字之前」的基线**逐项一致**（131/11 同一失败列表）。

### 阶段 3 — 接入 COW（默认转值语义）

1. 写路径（下标写 / `table_push` / `table_pop` / 字段重绑定）在**非 `shared`** 上改为：
   `h = tbl_cow(h)` → 写回槽 → 写。`tbl_cow` 已在（rc<=1 原样返回；rc>1 克隆+让出）。
2. **越界写**：COW 后 rc==1 ⇒ 照旧扩容。**rc 分流门禁可随之删除**——
   正确行为是「分离后扩容」，既不是中止也不是改到别人。
3. **`deep` 改走 COW**：rc 可信后，`deep` 的语义（入口分离）用 `tbl_cow` 即可，
   **免掉无条件克隆**（独占时零成本）。若 `deep` 与默认值语义重叠，可评估退役。
4. **`shared` 生效**：标了 `shared` 的形参/变量**跳过 COW** ⇒ 就地改、零拷贝。
   这就是「非 unsafe 下的高性能语法」。

### 阶段 3 — 进度（2026-10-05，提交 `1d648eb`）

**COW 已接入写路径，以 `TIE_TBL_VALUE=1` 为过渡开关，默认关。**

| 已接入 | 说明 |
| --- | --- |
| `table_push(t, v)` | 首参必为表变量 ⇒ 槽可得 ⇒ 写前 `tbl_cow` |
| `t[i] = v`（裸变量目标）| 同上；字段/下标目标本批不接，走原路径 |
| **值语义形参** | 非 `shared` / 非 `ref` 的表形参**入口 retain、出口 release 成对** |

**为什么形参要单独处理**：表实参按**借用**传递 ⇒ callee 内 rc=1 ⇒ COW 判成独占而写穿
（首次实测：`plain: ret=1 caller=1`，调用方被改）。入口 retain 使 rc=2 ⇒ 首次写触发分离。
`shared` 形参**跳过 retain/release 与 COW** ⇒ 零拷贝就地改——这就是它的高性能语义。

**开关关时逐字节等价**（硬证据）：同一探针的 `.ll`，接线前后 sha256 相同、大小相同
（`fad9cf88…`）、回归 210/11 FAIL 集合未变、不动点 `b9496bd6…`、零警告。
⇒ 「默认关」不是「大概没事」，是**生成代码完全没变**。

**开关开时四条行为同时正确**：

| 场景 | 关（现状） | 开（值语义） |
| --- | --- | --- |
| `var b = a; b[0]=99` | `a[0]=99` | **`a[0]=1`** |
| push 到副本 | `len(a)=2` | **`len(a)=1`** |
| 普通表形参 push | `caller=1` | **`caller=0`** |
| **`shared` 形参 push** | `caller=1` | **`caller=1`** |

**开时 tiec 不能自举**（二阶 `E00554 类型 'Value' 未定义` / `is_ws 无签名`）
——这正是 ~104 处依赖隐式共享的代码不再「碰巧工作」，即阶段 4 的迁移量。
⇒ **默认必须保持关**，直到阶段 4 完成。

**本批未接**：字段目标（`s.t[0]=v`）、下标目标（`t[i][j]=v`）、`map` 写路径。
它们的槽需要另外的写回路径（聚合字段 GEP / 外层表元素写回），留待阶段 4 一并处理。

### 阶段 4 — 迁移 ≈480 处

* 逐个判定：**本意共享** ⇒ 标 `shared`；**本意本地副本** ⇒ 保持默认（并顺手修掉
  那些「靠隐式共享碰巧工作」的代码）。
* 顺序：**先 tiec 自身（104 处）**——它是自举前提，不迁完无法验证；再 tlib（374 处）；
  最后 tiu（73 处，独立仓）。
* ★ 建议：加一个**过渡开关**（如文件级 `type tie<logic, table:legacy>` 或编译选项），
  让 tiec 能在迁移期间以旧语义自举，避免「迁一半编不动自己」的死锁。

## 3. 与规范的关系（需一并裁决）

## 4. 为什么不能一次做完

* 阶段 2 单独落地会让中间态**比现状更差**（中止取代静默），必须与 3 同批。
* 阶段 4 是 480 处语义判定，无法自动化（要判断「本意」），必须人过。
* 自举死锁：tiec 自身 104 处不迁完，编译器无法用新语义自举 ⇒ 需要过渡开关或分模块迁移。

⇒ **建议批次**：阶段 2+3 一批（含 tiec 自身迁移 + 过渡开关），阶段 4 的 tlib/tiu 各自成批。
