# tzp：tie 生态通用压缩格式族设计

*EN: tzp — tie Ecosystem Universal Compression Format Family — Design*

**日期** / Date: 2026-10-08  
**状态** / Status: 设计稿 v2.1 —— 理论设计完成；**§11 全部为待实测量，实测前不得当作结论**  
（v2.1 更正：tsha1 的位长参数**单位是 48 进制符号数**，不是二进制位 —— §6.2 与 §6.3 的取值已按 48 进制重算）  
**命名** / Name: 格式族名 **tzp**（用户裁决）。扩展名与产物命名见 §0  
**定位** / Scope: 跨领域通用压缩格式族。**从公理与形式模型出发**，不继承任何既有实现的取舍  
**关联** / Related: tie 生态格式与 API 家族（家族纪律 · 同源双态）· **tsha2**（哈希：三进制海绵 · 48 进制 XOF）· zd（拍平器的一个实现）· 诊断码体系  
**用户已裁决** / Decided by user:

- 字典一期由 tie 项目自行训练并作为生态资产分发（二期开放社区贡献）
- 全部哈希统一使用 **tsha2**（三进制海绵 · 48 进制 XOF · 输出长度即档位）
- 某些文件允许**以 zd 先拍平**，再进入压缩管线
- 格式族命名为 **tzp**

> EXEC BRIEF: One format family for every domain — a container + a layout layer + a five-stage  
> replaceable transform chain + a profile registry — instead of one format per field. Six axioms:  
> the file is a **function of the data** (never a record of the writing process); compression is a  
> **chain of transforms**; access is a **declared first-class property**; every declared knob must have  
> a **verifiable consequence**; decompression bounds come from **declared constants**; and one  
> (data, intent, version) maps to **exactly one byte string**. Sharding lives **only** in the layout  
> layer and is a **policy, never a core switch**: its unconditional gains are bounded decode memory,  
> parallelism and incremental resend, while random access is its weakest motive and is a net loss for  
> sequential scans. Sharding costs almost nothing in ratio **provided context can be externalized** —  
> which is precisely what the shared dictionary is for. Dictionaries are content-addressed,  
> independently distributable, sectioned, reproducible, append-only, and accepted only when their  
> **net benefit** (aggregate savings minus distribution and load cost) is positive. Hashing is  
> unified on **tsha2** (ternary sponge · base-48 XOF) with a per-use assignment of **output length** derived  
> from the *role* of each hash (integrity checks are compared against a stored expectation and need no  
> birthday bound; identities and dedup fingerprints create a name space and therefore must be sized by  
> the birthday bound). zd serves as one implementation of the representation-stage **flattening**  
> pre-encoder, and structure must always be compressed separately from payload.

## 0. 命名与范围 / Naming and Scope

- **族名**：`tzp`。
- **产物命名（提案，未裁决）**：单文件产物 `.tzp`；字典产物 `.tzpd`；魔数提案为 ASCII `TZP` + 版本 + profile（精确字节布局见 §12）。
- **范围**：跨领域通用压缩格式族 —— 文本、列式、记录、资源、帧流、时序、持久化、归档、镜像、去重。**领域不出现在格式里**，只出现在 profile 注册表中（§8）。

## 1. 公理 / Axioms

| 公理          | 内容                             | 若违反                    |
| ----------- | ------------------------------ | ---------------------- |
| **内容决定论**   | 文件是**数据的函数**，不是写入过程的记录         | 产物不可复现、无法跨实现对拍         |
| **可组合变换链**  | 压缩是若干**独立可替换的变换**串联，不是一个算法     | 每个领域各造一套格式，家族碎片化       |
| **访问是一等属性** | 访问意图**声明**，布局由意图**派生**，且一致性可断言 | 布局由写入者顺手决定，日后随机访问只能全解压 |
| **旋钮必须兑现**  | 任何声明必须有**必然后果**且后果可验证          | 格式说谎，且无人能发现            |
| **上界由常量决定** | 解压资源上界来自头中**声明的常量**，不来自文件大小    | 一个恶意文件即可耗尽内存           |
| **规范形式**    | 同一 (数据, 意图, 版本) ⇒ **唯一**字节串    | 多实现无法互操作，社区必分裂         |

*EN: content-determined / composable transforms / access as a declared property / every knob pays off /  
bounds from constants / canonical form.*

**每层参数的三个合法来源**：① 由数据确定性推导；② 由上一层推导；③ 显式声明在文件中。**不允许"写入者随意选择且不记录"**。

## 2. 形式模型 / Formal Model

```
数据 →(单元化)→ 单元树 →(布局)→ 块序列 →(变换链 + 封装)→ 字节流
```

- **单元** = `(键, 类型, 载荷)`。**领域不是格式**：领域 = 键方案 + 类型 schema。
- **块** = **最小可独立解码单位**。"分片"的定义就是块 —— 不是切字节，是切一个**自足的解码域**。
- 三个映射（单元化、布局、变换链）**必须确定性**。

通用性的全部来源就在这里：**格式只管三个映射，不管领域**。

## 3. 五层变换链 / Five-Stage Transform Chain

| 层       | 职责                                                   | 关键纪律                   |
| ------- | ---------------------------------------------------- | ---------------------- |
| **表示层** | 域预编码：delta · RLE · 字典 · 位打包 · 浮点拆分 · 预测 · **拍平**（§7） | 可逆、确定、显式声明             |
| **冗余层** | 跨块上下文：共享字典 + 匹配；内容定义去重                               | 上下文**可外置**（分片不损压缩率的前提） |
| **熵层**  | 上下文建模 + rANS / tANS，逼近熵极限                            | 块内状态必须可确定性重建           |
| **布局层** | 单元树 → 块序列 + 两级索引                                     | **分片与随机访问只在这一层**       |
| **封装层** | 头 · 校验 · 版本 · 扩展                                     | 不含任何领域语义               |

每层独立版本化、独立替换；表示层预编码器与 profile 均为**注册表**。

## 4. 布局层：块与索引 / Layout: Blocks and Index

### 4.1 块

- 块边界由**内容决定**：语义键排序，或内容定义边界。**不得**依赖写入顺序、缓存、并发调度。
- 块是**资源上界单位**：头里声明 `max_block_raw`，解压前校验（同时挡住放大炸弹）。
- 形态：`块头` + `载荷` + `校验`。**块内不得引用其他块**（唯一例外：引用字典节，§5.3）。

### 4.2 三档布局（显式声明，且必须与实际结构一致）

| 档      | 含义           | 压缩率代价 | 适用              |
| ------ | ------------ | ----- | --------------- |
| **固实** | 单流，块不独立      | 无     | 归档、顺序读、整体消费     |
| **分组** | 块独立可解 + 共享字典 | 小     | 默认；绝大多数场景       |
| **独立** | 块完全独立，无共享状态  | 大     | 并行优先、随机读优先、流式到达 |

### 4.3 两级索引

- 索引的理论要求：**可顺序二分**（条目定长）、**自相似**（自身也用同族编码）、**可截断**（只加载前缀）。
- 三条合起来 ⇒ **锚点表 + 叶表**。**条目数必须亚线性**：记录级索引会随数据线性增长，把"不必全解压"变成"把问题搬到索引上"。
- **锚点表按键排序**（排序由内容决定，写入顺序不行）。
- 锚点密度 `K` 是**派生量**（由目标寻址成本与内存预算反解），不是格式常量。

## 5. 字典 / Dictionary

### 5.1 地位与形态

字典一期由 tie 项目自训（用户裁决），因此它是**要长期持有、分发、背书的公共资产**，不是压缩器内部参数。

- **内容寻址**：字典身份 = tsha2 指纹（§6）。文件只写 `dict_ref`（指纹），不写编号 —— 编号可被重排，指纹不能。
- **独立文件**：字典自身用**本格式族**编码（自相似）⇒ 存在一个解码器即可读字典。
- **可分节**（§5.3）：否则字典会成为新的全量前置负担。
- **可缓存 / 可离线预载**：一份字典服务多个产物。这是"大量小文件"场景的**唯一有效杠杆**。
- **不可递归**：字典**不得**依赖其他字典 ⇒ **前置依赖深度恒为 1**。
- **换代只追加**：主字典稳定，新能力以"新节"追加；换主字典 = 断代，老字典必须长期可用。

### 5.2 设计一：自足性与依赖语义

**声明**：两档 + 一个可选属性。

| 档             | 读端可依赖的硬承诺               | 写入器义务                             |
| ------------- | ----------------------- | --------------------------------- |
| **自足** self   | 不依赖任何外部资源；字典若存在必须内嵌于本文件 | 必须内嵌字典；不得引用任何未内嵌的指纹               |
| **外链** linked | 允许引用外部字典                | 必须写明 `dict_ref` 与节集合；**不得**内嵌整本字典 |

**可选属性** `minimal_embedded`（最小节内嵌）：仅对**外链**有意义 —— 缺主字典时仍能解出**元数据与目录级信息**。

**依赖语义（逐条）**

1. **依赖对象唯一**：只有字典一种外部依赖；禁止引用外部块、外部索引、外部 schema。
2. **可判定性**：`dict_ref` 是 tsha2 指纹 ⇒ "手上这本字典是不是它"**可判定**，无需信任声明。
3. **闭包检查可静态执行**：声明**自足**的产物，其依赖闭包必须 ⊆ 内嵌集合 —— 只查头与索引，**不需解压任何载荷**；一致性测试强制项。
4. **校验顺序**：先校前置（字典指纹、节可得性），**再**解块。前置指纹不匹配 ⇒ **拒绝**，不做"尽力而为"。
5. **错误分类必须区分**：
   - **缺前置** = 可恢复（补上某指纹的字典/节即可解，报出缺哪个指纹、缺哪些节）；
   - **损坏** = 不可恢复（校验失败、索引越界、块头非法）；
   - 声明**自足**却缺前置 ⇒ 按**损坏**处理（该产物承诺过无依赖）。
6. **失败前置性**：前置不足必须在解任何块**之前**报出。
7. **降级读**：`minimal_embedded` 存在时，缺主字典 ⇒ 允许产出"最小节覆盖的部分"，但必须**明确标记为降级**，不得静默返回部分数据。

### 5.3 设计二：分节方案

**节的划分原则**：节 = 一个**上下文域**。太粗（按 profile 划）失去共享精度，太细（按文件划）失去共享本身。

**一期节集合（只追加）**

| 节         | 覆盖的上下文            | 主要受益         |
| --------- | ----------------- | ------------ |
| **文本节**   | 词、常用子串、标点与空白模式    | 文本、记录型元数据    |
| **源码节**   | 关键字骨架、缩进模式、标识符前后缀 | 源码、schema 定义 |
| **键名节**   | 重复出现的键名、列名、枚举值    | 记录、列式        |
| **数值节**   | 预编码后的**残差高频模式**   | 列式、时序（收益待实测） |
| **资源残差节** | 已是压缩格式的资源头部/尾部残留  | 资源           |

**不设领域字典节**（如"某游戏节""某模组节"）：领域相关超出注册表边界，属二期社区贡献范畴。

**引用机制**

1. 节的语义由 **tsha2 指纹**绑定（§6）。
2. **文件内短编号**：块头必须短 ⇒ 文件内用短编号引用节；短编号是**局部命名**，其语义由文件内"短编号 → 节指纹"映射表绑定，该表**按节指纹排序**（内容决定）。
3. **节集合表**：避免每块重复列举节号 ⇒ 产物内有一张节集合表（**排序且去重**），**块头只引节集合 id**。
4. **前置加载粒度 = 节**，禁止更细（否则前置解析变递归、成本不可预算）。
5. **推论**：读一个块所需的全部前置 = 该块引用的节集合 ⇒ **读一块的成本可预算**（§5.4 中 `load_cost` 的可计算性来源）。

### 5.4 设计三：净收益函数与实测方案

对字典 `d`：`F(d)` = 引用它的产物集合；`C(f, d)` = 产物压缩后字节；`C(f, ∅)` = 不用字典时字节；`|d|` = 字典字节（只计一次）；`L_f(d)` = 每次使用的前置加载成本（字节等价，由节集合决定，可计算）。

```
N(d) = Σ_{f ∈ F(d)} [ C(f, ∅) − C(f, d) ]  −  |d|  −  Σ_{f ∈ F(d)} L_f(d)
        └──────────── 总增益 G(d) ───────────┘   └分发┘  └── 加载 ──┘
```

**三条推论**

1. **字典大小的最优值**由 `dN/d|d| = 0` 给出：**边际增益 = 边际分发成本** ⇒ "该多大"是解出来的，不是拍出来的。
2. **训练停条件**：新增词条不再提升 `N(d)` 即停。
3. **单产物启用判据**：`C(f, ∅) − C(f, d) > L_f(d)`。由此得两条**可证伪预测**：文件越小收益越大；**单个大文件不启用字典**。

**训练器附加约束**

- **最小文档频率阈值**：只在一个产物中出现的词条属于该产物的载荷，不得进字典。
- **留出集**：必须在未参与训练的语料上仍为正收益，否则视为过拟合。
- **可复现**：语料以 tsha2 指纹清单冻结；同语料 + 同参数 + 同版本 ⇒ **字典逐字节相同**。

**实测协议**

| 项    | 规定                                                              |
| ---- | --------------------------------------------------------------- |
| 对照组  | 四组：不用字典 · 只用一期内置字典 · 字典大小多档扫描 · 不同节集合组合                         |
| 语料   | **必须真实语料**（禁手写样本）。三类：大量小文件 · 中等结构化文件 · 大文件（大文件组用于**证伪**"不启用"预测） |
| 指标   | 压缩后总字节（含字典分摊）· 单产物平均体积 · 解压吞吐 · 解压峰值内存 · 前置加载字节 · 缺前置失败率        |
| 判定   | `N(d) > 0` 且存在峰值档 ⇒ 取该档；否则不启用字典                                 |
| 反例检查 | 语料必须含"**应当不启用**"的样本，并断言其确实未被启用（只测正例不算验收）                        |
| 复现断言 | 训练两次（同语料同参数）⇒ 字典指纹相等                                            |
| 泛化断言 | 留出集上 `N(d) > 0`                                                 |

## 6. 哈希：tsha2（三进制海绵 + 48 进制 XOF）/ Hash Assignment

### 6.1 三个角色（分配的全部依据）

哈希在格式里只干三种活，**三种活的安全性要求完全不同**：

| 角色          | 是什么                        | 碰撞的后果                 | 是否构成"名字空间"              |
| ----------- | -------------------------- | --------------------- | ----------------------- |
| **完整性校验**   | 与**存下来的期望值**比较，判断字节有没有被改/坏 | 漏检 ⇒ 数据坏了但被当作好的       | **否**（比较对象是固定的期望值，不是彼此） |
| **身份 / 名字** | 字典、节、结构指纹 —— 用摘要**指代**一个对象 | 两个不同对象同名 ⇒ **静默用错对象** | **是**                   |
| **去重指纹**    | 大规模块的等价性判定                 | 误判等价 ⇒ 数据丢失           | **是**（但可加二次比对兜底）        |

**关键区分**：完整性校验**不需要生日界**（它不建立名字空间），身份与去重**必须按生日界取长**。把两者混为一谈，是压缩/存储格式里最常见的长度浪费与安全隐患来源。

### 6.2 位长的量化取法（⚠ 单位：48 进制符号）

**单位约定**：位长参数 `n` 的单位是 **48 进制符号数** —— 不是二进制位，也不是字节。**tsha2 的每个输出符号携带 5.28 位**（实测口径：10 个 trit → 3 个符号，`10·log₂3 = 15.85` 位 ⇒ `15.85/3 = 5.28` 位/符号）：

```
等效强度（位） ≈ n × 5.28
```

（`48 = 16 × 3`；tsha2 的输出是"**每 10 个 trit 直接写成 3 个 48 进制符号**"（`3^10 = 59049 ≤ 48^3 = 110592`）⇒ **无损、无偏、可逆**，因此**不再有名义/实际折算**。）

- **完整性**：单次误接受概率约 `2^-(n×5.28)`。按生命周期 `10⁹` 次校验估算：
  - `n = 8`（≈42 位）⇒ 期望误接受 `≈ 2.3×10⁻¹³` —— 可忽略；
  - ⇒ 完整性校验取 **8–12 符号**（`blk` 若走非加密原语则只 8–16 字节，见 §6.3）。
- **身份 / 去重**：碰撞概率约 `m² / (2 × 48ⁿ)`（`m` = 生命周期内对象总数）。要求低于 `2⁻⁶⁴`：
  - `n > (2·log₂m + 63) / 5.28`；
  - `m = 10⁹` ⇒ `n > 22.3` ⇒ **取 24 符号**（≈127 位）。  
    ⇒ **身份取 24 符号**。
- ★★★ **tsha2 消除了 tsha1 的两个结构性缺陷**（实测对照见 §6.6）：
  1. **无名义/实际折算**：tsha1 的可达输出空间只有名义的 **83–88%**（`n×5.585` 是名义值）；tsha2 的输出映射是**无损无偏**的 ⇒ **上面的数字就是实际值**。
  2. **无"空转档位"**：tsha1 的 17 档里 5 档映射到同一内部状态（`n=16` 同 `12`、`n=96` 同 `92` 等）⇒ 白涨体积；**tsha2 的输出是 XOF —— 每多要一组符号就多跑一轮置换 ⇒ 每一档都是真实台阶**。

### 6.3 一期分配表

| 用途           | 域标签   | 角色       | 数量级            | 模型                          | 位长（符号数） | 等效强度   | 理由                                                                        |
| ------------ | ----- | -------- | -------------- | --------------------------- | ------- | ------ | ------------------------------------------------------------------------- |
| 块载荷校验        | `blk` | 完整性      | 每块（10³–10⁶/产物） | **tsha2-r**（4-lane 嵌入式档，~200 MB/s）或非加密校验原语 | 8–16 B  | —      | r 档速度已可承担逐块哈希；若流水线更快，换非加密原语                      |
| 索引段自校验       | `idx` | 完整性      | 每产物 1（或每叶 1）   | **tsha2**                   | **16**  | ≈84 位  | 数量少，无需更强                                                                  |

### 6.4 声明与解析纪律

- **产物必须声明**：模型码 + 位长（**符号数**）+ base。**缺任一项 ⇒ 拒绝**，不得由实现者默认。**tzp 一期固定 `base = 48`**；读到非 48 的 base ⇒ 拒绝（开放其他进制度属主版本变更）。
- **哈希方案表**：产物头里放一张表（用途 → 模型码 + 位长 + base），各引用点只写**用途 id** ⇒ 避免每处重复写模型与长度。
- **编码形态**：符号按其字符码**一符号一字节**原样存 ⇒ **摘要字节数 = n**（12 符号 ⇒ 12 字节；24 符号 ⇒ 24 字节）。此形态每字节只承载 `log₂48 ≈ 5.585` 位，相对理论最优打包**浪费约 30%**，换来的是**字节对齐、可打印、自描述**；一期接受该浪费（生态既有做法一致：快校验档 = 8 符号 = 8 字节）。理论最优打包需处理非字节对齐的大整数运算，列为后续优化项（§11）。
- **域分隔**：哈希输入 = `域标签 ‖ 数据`，域标签为固定 ASCII（§6.3 表列出的 `blk`/`idx`/`dic`/`sec`/`sch`/`ded`/`cor`/`dep`）⇒ 同一位长在不同用途之间**不得互相冒充**。
- 校验策略：**全部必检**（不是可选）。
- ⚠ **实现侧对非法位长 / 非法 base 静默返回空串**（实测行为）⇒ 读端**不得**把空串当作校验信号（否则"非法参数"与"校验失败"不可区分）；**非法位长、非 48 的 base、非合法符号字节，一律在解析头（或引用点）时即拒绝**。

**tsha2 的轮函数（定稿 v2，2026-10-09 第二轮实测修订）**

```
状态 = N 个子 lane（每子 lane 64 trit，双平面编码，规范性 高平面 & 低平面 == 0）
伙伴 = 双向环：y1 = (i+1)%N，y2 = (i−1+N)%N          ★ 修订：旧版 (i+1, i+3) 是二部式耦合 ⇒ 扩散坏尾巴
混合：lane_i ← lane_i + rot_k1( y1 × (y1 + c_i) ) + rot_k2( y2 × (y2 + c_i) )   （逐 trit mod 3）
常数：c_i = 1+(i%2)，k1 = (i*7+5)%64，k2 = (i*11+23)%64
更新顺序（★ 修订）：偶数子 lane 先（伙伴全为旧值 ⇒ 彼此独立）、奇数子 lane 后（伙伴全为新值 ⇒ 彼此独立）
  ⇒ 串行深度 2、ILP 最大；**构造性可逆保持**（逆序 = 先恢复奇数、再恢复偶数）
输出层：48 进制 XOF（10 trit → 3 符号，无损无偏）
```

**两轮实测修正记录（2026-10-09 晚）**
1. **旧扩散测量有系统性伪象**：单 trit 翻转写成 `低平面 |= 1` / `^= 1` —— 前者 50% 概率**空翻**，后者在该列基值为 2 时产生**非法 trit (1,1)**，而非法 trit 在位平面加法器中与合法值碰撞（`3+p` 的映射在 p=2 时与 `2+p` 重合）⇒ 差分静默死亡。修复 = **保范翻转**（高平面 bit 为 1 则翻高平面，否则翻低平面）。⇒ 旧数字（270‰ / 330‰ / 613‰）全部作废，以本版为准。
2. **拓扑才是主瓶颈**（修正"分叉因子"旧说）：修复测量后，(i+1, i+3) 在 6/12 lane 上均值 595/336‰ 且存在 min=197/92‰ 坏尾巴；**双向环 (i+1, −1) 使任意 N 的环形耦合闭合** ⇒ 6/12 lane 扩散 665/662‰（理想 667‰）。4-lane 一直暗合双向环，这才是它" lane 少反而好"的真正原因。
3. **跨列积（χ 式）被速度否决**：`y×(rot(y)+c)` 或 `y×(y₊₁列+c)` 在乘法前多一级串行 ⇒ **速度减半（141→70-72 MB/s）**，扩散仅 +16‰（679 vs 663）⇒ 不值。保留 embed 结构（乘 → 旋转 → 加）。
4. **GF(3) 事实更正**：`y ↦ y(y+c)` **不是** GF(3) 双射（二次式在 GF(3) 上恒有根；c=1 时 0、2 → 0）。可逆性并不依赖它——逆推只需 `i = i_new − Σ rot(乘积项)`（乘积项可由伙伴旧值重算），差分安全性也不因非双射而塌方，但**设计稿不得再宣称"逐列双射"**。另：GF(3) 上全部 6 个置换都是仿射的 ⇒ **逐列非线性双射不存在**，非线性必须跨列或取非双射二次型。
5. **x 档重定义（两步）**：旧案"6 lane×128 列 + 3 伙伴"两处否决——(a) 若伙伴取"邻 lane 同一半"（子 lane j ↔ j±2），前后半是**两个独立 384-trit 系统**（跨半扩散 = 0，安全减半）；(b) 修复为子 lane 环 ±1 后与 b 档**逐位同构**（verify 数字完全一致），且吸收管线更慢（109 vs 159 MB/s）⇒ 旧案无独立价值。**最终 x = 大状态档：24 子 lane（1536 trit），R=16，容量 ~608 位抗碰撞，85–100 MB/s**（16 子 lane 配置实测通过但按用户裁决归档）。宽速率需求由 **f**（rate 64B，~202 位抗碰撞，150–184 MB/s）承担。
6. **`inline` 纪律**：LLVM 未自动内联元组返回的混合函数（-l2 下 31 个调用点残留）⇒ **5× 减速（150→22 MB/s）**；`inline func` 强制后恢复。混合函数必须显式 `inline` 并用 opt 后 IR 复核调用点为 0。

**入库版修订（v2.1，2026-10-09 晚，tsha2 入库烟雾测试暴露）**：
1. **θ 步（Keccak 列奇偶扩散的三元版）**：P_c = Σ_lane lane_i[c]（mod 3），lane_i += rot(P, i*3+1)。
   纯加性 own 项使被吸收的消息 trit 在源 lane **永久加性残留**（短消息四档同输出、空消息输出
   大片零、容量 lane 恒零 ⇒ 档位安全声明对短消息落空）——φ/Feistel 与稠密 F 均不足以修复
   （F 的乘积在稀疏态下同样退化为零），θ 一轮即把任意列内容扩散到全部 lane。**N ≢ 2 (mod 3)
   ⇒ θ 可逆**（12/24 ≡ 0，4 ≡ 1 ✓），轮置换双射性保持。
2. **填充改为 Merkle–Damgård 强化**：0x80 + 补零 + 尾块末 8 字节小端消息长度——

4. **KAT**（跨语言对拍基准，各语言移植必须逐字节一致）：见 std/tsha2.tie 头部
   （r/f/b/x × 空串/"123456789" × 8/46 符号）。
5. **tsha2.tie 已入库**（std/tsha2.tie，四档 XOF），tink_v2 已迁移（ext key 更名

2. **x16 与 x24 的取舍**：实测 x16 性价比更高（快 ~10%、405 位已远超所需、体积差 ~5 KB）；**用户裁决取容量优先：x24 更名 x，x16 归档**。
3. **最终家族（用户裁决 2026-10-09）**：**r / f（=b64，12 lane rate 64B）/ b（12 lane rate 48B）/ x（=x24，24 lane R=16）**。f 与 b 共用置换。

**强度（诚实声明）**：抗碰撞由容量界定。`r` 档容量 1 lane = 64 trit ≈ 101 位熵 ⇒ **抗碰撞约 50 位**，**不足以做身份指纹**，只适用于嵌入式完整性校验；身份类用途（`dic`/`sec`/`sch`/`cor`/`dep`）用 `b` 档（容量 384 trit ≈ 608 位熵 ⇒ 256 位级）；`f` 档（202 位级）是 b 的宽速率变体，适用于仍满足 128 位下限的高速大流量场景；`x` 档（608 位级）为超规格长期档。

**大状态档（b，12 lane）的实测结论（2026-10-09 第二轮）**

| 维度 | 实测 | 判据 |
|---|---|---|
| **速度** | **132–159 MB/s**（R=12；R 敏感性：R=10 出现 min=250‰ 坏尾巴 ⇒ R=12 为下限）；f（rate 64B）**150–184 MB/s** | 倍增法线性 + 换种子读数不变 |
| 容量 | 384 trit = **608 位熵** | ⇒ 256 位级抗碰撞（sponge 容量 ≥ 2×256 位） |
| **置换可逆性** | 300 个规范随机初态（全 64 位范围）× R=12 ⇒ **输出零重复**；构造性可逆 = **偶先奇后两相更新**的逆序恢复（先奇后偶） | 每个子 lane 自身值只经加法进入输出 ⇒ 逆推无需invert 乘积 |
| **扩散** | **R=12：avg 662‰ / min 634‰**（16 seed；理想 ≈ 667‰）；R=6 245‰、R=8 506‰、R=10 626/250‰ | 修复保范翻转后多 seed 统计 |
| **抹平（状态合并）** | 逐轮 1..R **0 次**（最小逐轮差 491/768） | 判据：base 与翻转态**整状态相同** |
| 输出层 | **48 进制 XOF**（10 trit → 3 符号） | `3^10 = 59049 ≤ 48^3 = 110592` ⇒ 无损无偏可逆 |
| 确定性 / 敏感性 | PASS / PASS | 改 1 字节 ⇒ 输出全变 |
| 对标 | tsha1 **19 MB/s** · SHA-256 软件档 50–150 MB/s | ⇒ **超过 SHA 软件档上沿，比 tsha1 快约 8 倍** |

**块级校验（改变 §6.3 一行）**：用 **tsha2-r（4-lane 嵌入式档）** 承担逐块哈希 —— 体积最小；若流水线仍更快，可换**非加密校验原语**。身份类用途（`dic`/`sec`/`sch`/`cor`/`dep`）一律用**大状态档（b，12 lane，容量 608 位熵 ⇒ 256 位级）**。

**tsha1 退役说明**：tsha1 的根因已定位并记录（有效输出空间只有名义的 **83–88%**，成本 ≈ **50 指令/字节**，且 17 档里 5 档映射到同一状态）⇒ **不再用于任何新字段**，仅保留为历史兼容读。

### 6.7 差分/线性传播界（DDT/LAT，2026-10-09 已完成）+ 未完成项与门禁

**DDT/LAT 结论（探针 `tzp_ddtlat.tie`，判据事先登记，全部实测）**
1. **电路级 DDT：PN 达标（精确）**。逐列非线性项经真实位平面电路逐值计算：
   g_1 = {0→0, 1→1, 2→0}，g_2 = {0→0, 1→2, 2→0}；**两个非零 Δin 行均恰为 (1,1,1)**
   ⇒ **差分均匀度 = 1/3 = 理论理想**（GF(3) 二次型 = planar/完美非线性函数，导数全平衡）。
2. **电路级 LAT：PN 水平**。16 个非平凡线性掩码中 4 个平衡（|W|=0）+ 12 个 |W|=√3（随机水平），
   **0 个线性相关 = 1 的掩码**；最大概率偏差 = 1/3（PN 水平）。
3. **实现与设计偏差（须记录）**：`tc_add(·,2)` 实际计算 `2−y` 而非 `y+2` ⇒ c=2 lane 的乘积
   = −y(2−y) = y²−2y ≡ y(y+1)，与 c=1 的 −y(y+1) 互为相反数 ⇒ **全部 lane 实际使用同一 PN
   函数（up to 输出符号）**——"c 交替 1,2"的设计意图未实现；但两映射均为 PN ⇒ 安全性质不变。
4. **密码级差分（b 档，M=2000，64 抽样位置，状态 12 轮白化后注入保范单 trit 差分）**：
   R=12 残留位置级偏倚（Δ=+1 类 max χ²=41，14/64 超阈；Δ=−1 类干净）；
   **R=16 完全干净（max χ²=7.6，0 超阈）** ⇒ R=12 混合余量有限，残差随轮数衰减消除。
5. **局域化特征（解析-实测精确吻合）**：单列差分 1 轮后保持局域化的概率 = **2/9 ≈ 222‰**
   （实测 221‰）：两伙伴读同一被翻转值 ⇒ 乘积差死亡完全相关（v=2 分支贡献 4/27、v=0/1 各 1/27；
   旧预测 1/9 作废——未计相关性）。该特征**不构成碰撞路径**：自身加法项使差分在源 lane
   永不自动消亡，只能靠乘积项随机抵消；仅量化"慢扩散尾部"。
6. **线性掩码扫描：通过**（24 组单位置关系，R=12，M=2000：最大偏差 43 计数 = 2.1%，
   低于 4σ 阈值 84；随机期望 ~17）。

**剩余安全缺口**：**外部审查未做** ⇒ 仍不得宣称"安全性顶尖"。
**R 取舍新数据点**：R=12 的混合残差（~5% 位置级偏倚）在 R=16 消除 ⇒ 若要更大余量，
f/b 可升 R=16（速度 −25%），待用户裁决。

**实现门禁（每次改动必跑）**
1. **电路逐值自检**：mod-3 加法 / 乘法各 9 种输入 + 32 道并行（乘法平面归属对照 GF(3) 九九表）；
2. **状态规范性**：任意时刻断言 `高平面 & 低平面 == 0`；
3. 确定性（同输入两次逐符号相同）；
4. 敏感性（改 1 字节 ⇒ 输出必变）；
5. **扩散**：同一 R 下 base vs 翻转，多 seed 统计 avg/min（基线 667‰，够用线 550‰）；
6. **单射性**：N 个随机初态跑 R 轮，输出零重复；
7. **展开实现与参考实现等价性**（防手工展开笔误）；
8. **DDT/LAT**：电路级 PN 断言（§6.7.1/2）+ 密码级 χ²（R=12/16 门禁）；
9. **速度**：倍增法（2×/10× 看线性）+ **构建指纹** + `&&` 串联编译。

**工程纪律（两轮血泪）**
* **单 trit 翻转必须"保范"**：翻 l 平面 bit 而该列 h 平面 bit 为 1 ⇒ 产生非法 trit (1,1)，在位平面加法器中与合法值碰撞 ⇒ 差分静默死亡；`|1` 还有 50% 空翻。⇒ 翻转前看 h 位：h=1 翻 h，否则翻 l。
* **统计函数必须对输入全域正确**：`popcnt` 若写成 `while x > 0`，**负数直接返回 0** ⇒ 曾把扩散率系统性低估一半、并伪造出大量"抹平"假象。⇒ 逐位取 `((v>>i)&1)`，并用"第 63 位为 1"的样例自检。
* **判据必须用事件的真定义**：抹平 = 两侧同时为 0（不是任一侧为 0）；"满扩散全变"在理想对象上**不可达**（`P=(2/3)ⁿ≈0`），基线只能用 667‰。
* **随机状态必须全 64 位范围**：31 位小状态会系统性抬高扩散读数（旧 4-lane 613‰ 即此伪象）。
* **LCG 低位 bit 周期为 2** ⇒ 任何依赖状态低位统计的探针必须先做全扩散白化（12 轮）再采样；本轮 DDT/LAT 的 χ² 异常与局域化预测偏离均源于此（已登记的纪律仍踩了一次）。
* **统计期望按实际类样本数计算**：翻转差分符号类不对称（Δ=+1 占 2/3、Δ=−1 占 1/3）⇒ 混合分布 ≠ 条件分布，χ² 期望必须分类计算；多组统计共用一张计数表时必须用 base 偏移分段（本轮表冲突造成过假 χ²=25928，超过数学上限 4004 ⇒ 一眼可识破）。
* **元组返回的混合函数必须显式 `inline`**：LLVM 在 -l2 下不自动内联 ⇒ 每轮 6-12 次真实调用 ⇒ 5× 减速；用 opt 后 IR 复核调用点为 0。
* **乘法前不增加串行级**：跨列积（χ 式 `y×(rot(y)+c)`）会把速度砍半而扩散仅 +16‰ ⇒ 保持"乘 → 旋转 → 加"的 embed 结构。
* **可逆性论证的正确形式**：子 lane 自身值只经**加法**进入输出、乘积项可由伙伴值重算 ⇒ 逆序逐 lane 恢复；不要依赖"逐列映射是双射"（GF(3) 的 6 个置换全是仿射的，二次式恒有根）。
* **tie 语义硬事实**：`>>` 是**算术右移**（`-8>>1=-4`）⇒ 循环移位必须掩码右移结果；**两个 64 位平面不可打包进一个 i64**。
* **计时**：`mono_ms()`（GetTickCount）粒度实测 **15–16 ms** ⇒ 任何 <100 ms 的测量不可信；消息必须**运行期生成**（常量消息会被常量折叠）。

## 7. 拍平：以 zd 为表示层预编码器 / Flattening

用户裁决：某些文件允许**以 zd 先拍平**再压缩。为避免把"结构化"压成不透明字节流，拍平被定义为**表示层的一个预编码器**，并规范其接口。

```
拍平(值, schema) → (结构描述, 载荷流)
还原(结构描述, 载荷流) → 值
```

* **zd 是该接口的一个实现**（用户裁决的落地方式）。规范只依赖接口，不依赖 zd 的任何具体位或段。
* **必须产出两件东西，且分开压缩**：
  1. **结构描述**（schema / 键 / 类型）—— 重复度极高 ⇒ 走**键名节 + 字典**，以其 `sch` 指纹为身份；
  2. **载荷流**（数值与字符串本体）—— 走**表示层预编码**（delta / RLE / 位打包）再进熵层。
* **禁止**把 zd 的完整字节当单个不透明 blob 丢给熵层 —— 那等于放弃"结构可预测"这个最大的冗余来源。
* **schema 必须随产物记录**；演进只追加字段，并在结构描述里带三态（有效 / 弃用 / 移除），保证老产物可读。
* **风险与验证**：拍平改变载荷字节形态 ⇒ 必须做**往返验证**（拍平→压缩→解压→还原，逐字段相同）与**跨实现一致性**（同值同 schema ⇒ 同字节）。

## 9. 硬不变式 / Hard Invariants

1. 头自校验，且头是**第一优先解析对象**（可独立判定"能不能读、要不要前置、上界多少、哈希方案是什么"）。
2. 文件尾存在不少于 32 字节的零填充区（越界读安全 + 内存映射可零拷贝）。
3. 单元管语义、块管寻址；**块内不得引用其他块**（唯一例外：引用字典节）。
4. 索引位于文件尾；**无索引的单流形态合法**（退化档）。
5. **所有顺序与编号由内容决定**：禁止时间戳、随机数、主机/路径信息、构造期 id、遍历序。
6. 同一 (数据, 意图, 版本) ⇒ **逐字节相同**；跨语言实现必须能断言字节相等。
7. 所有校验**必检**；校验覆盖范围（含填充字节与否）逐字段精确定义。
8. `max_block_raw`、`dict_max`、`index_entries_max` 为**硬上限**，解压前校验。
9. 声明的**布局**与**自足性**必须与实际结构一致，且**可静态断言**（不需解压载荷）。
10. 处理顺序固定：**去重 → 分块 → 压缩 → 加密**。加密必须是**块级独立 AEAD**（每块独立 nonce），禁用链式模式。
11. **未知 flags 位 ⇒ 拒绝**（不可信）；**未知扩展键 ⇒ 跳过**（向前兼容）。两者策略不同，必须显式区分。
12. 格式错误**不 panic**；返回可检查结果 + 诊断码，且**区分"缺前置"与"损坏"**。

*EN: header self-verifying and parsed first / ≥32B zero tail / no cross-block references / index at
tail with indexless streams legal / all ordering content-determined / exactly one byte string per
(data, intent, version) / all checks mandatory with exact coverage / three hard caps verified before
decode / layout and self-containment statically assertable / dedup→block→compress→encrypt with
per-block AEAD / unknown flags rejected, unknown extension keys skipped / no panic, and "missing
prerequisite" ≠ "corrupt".*

## 10. 演进与社区 / Evolution and Community

* **主版本不兼容，次版本只追加**；五层各自版本化。
* **注册表化**：预编码器、profile、节类型、哈希用途均为注册表，插件式扩展，不改格式。
* **每个登记项必须带**：跨实现一致向量（KAT）· 一致性测试 · 资源上界声明（"旋钮必须兑现"的机械化执行）。
* **哈希方案的演进**：新增用途 = 注册新域标签；**改变既有用途的模型或位长 = 主版本变更**（否则老产物语义漂移）。
* **字典即社区资产**：一期 tie 项目训练并内部分发（信任 = 内置白名单 + 内容指纹）；二期开放社区贡献领域字典 —— 此时**指纹只保证完整性、不保证来源** ⇒ 必须引入**来源签名**，因此**签名字段与信任策略声明一期就要留位**。
* **字典保留义务**：被引用过的字典必须长期可取。保留策略与命名谱系属于格式承诺，不是运维细节。
