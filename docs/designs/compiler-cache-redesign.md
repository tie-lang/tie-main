## 一、现状与缺陷分析

### 1.1 现行缓存机制（p.9.1.3，`tiec/compiler/driver.tie`）

缓存键 = 入口「#cfg 预裁剪」源码 + 输入/输出路径 + 优化档/目标/角色/shared/emit_ir/
fast_math/bounds + 手动盐（`g_cache_salt="tiec-cache-v1"`）拼接后经弱滚动哈希
（`str_hash`：多项式 31 mod 2^31-1）。命中则 `file_copy(缓存产物 → 目标)` 并跳过整条
编译管线；未命中编译完成后把最终产物 `file_copy` 入缓存目录（`cache.dir` 或 `~/.tiec-cache`）。

### 1.2 四类确认缺陷

1. **陈旧缓存（严重、已确认）**：缓存键哈希的是 `cfg_preproc.preprocess` 裁剪后的**入口
   源码**，而该阶段只做 `#if cfg()` 行裁剪、**不展开 import**；import 文件在语义阶段
   `semantic.expand_imports` 才从磁盘读取。**修改任一 import/using 依赖文件不改变缓存键，
   tiec 直接返回陈旧产物。** 现状仅对无 import 的单文件程序正确。已有旁证：`_slim.tie`
   `rebuild-bump` 注释记明 *“cache key does not cover imports”*。

2. **碰撞静默错产物（安全）**：31 位多项式滚动哈希键空间过小，真实工程尺寸下碰撞不可忽略；
   又有 `file_exists(ck)` 命中即复制，**命中产物无二次指纹核对**——碰撞返回错误产物无告警。

3. **无增量（性能）**：只缓存最终产物（.exe/.dll/.a/.ll），无 IR/opt 中间层；多文件工程
   任一小改动即全量重编（前端 + 中端 + 后端 + 链接），增量收益为零。

4. **磁盘无限增长 + 非原子写（工程）**：缓存目录每个唯一键永久累积 `.cache`，无容量上限、
   无淘汰；`file_copy` 中断可留下不完整缓存文件，后续命中 `file_exists` 可能误判为有效。

> 定位裁决（务实）：本次为**完整重构**，一次性覆盖以上四类缺陷；按子项分期交付，每期
> 单独可验收、回归不劣化。

---

## 二、目标与定界

- **修复**：依赖感知（import 变更必失效）；碰撞免疫（强哈希 + 产物指纹二次核对）。
- **提升**：内容寻址去重存储；中间级（IR/opt）增量缓存，支撑多文件工程小改动增量编译。
- **治理**：原子写（临时文件 + rename）+ 可配置淘汰（手动 `--cache-clean` + 容量/条目上限）。
- **不纳入**（本次不做，接口预留）：
  * 常驻后台守护 / 自动后台淘汰线程（避免引入常驻进程状态；淘汰仅在编译入口顺带触发）。
  * `--jobs` 并行编译的多线程 cache 并发写入优化（并行管线本身仍留 p.9.1.3 异步落地，
    但本重构保证缓存读写在**串行单进程路径**下原子、确定、无数据竞争；若将来并行化，
    内容寻址天然兼容并发写）。
  * 编译产物本身格式/语义变化（不动 `compile_logic/library/shared` 产物语义，仅接缓存层）。

---

## 三、方案总览

内容寻址（Content-Addressed Storage，CAS）为轴，串联五项设计：

- 缓存对象以**内容指纹**为名（`objects/<tsha1r 指纹>`），天然去重、天然依赖感知——只要
  把所有参与编译的输入（入口源码 + 全部 import/using 依赖文件字节）的指纹聚合为构建键，
  任一输入变化即得新键。
- 命中路径做 **tsha1r 二次产物指纹核对**，防碰撞、防磁盘残缺/被篡改。
- **原子写**：先写临时文件，`rename` 到终名，杜绝半截缓存。
- **中间级（IR/opt）分层缓存**：为多文件增量编译提供复用粒度。
- **淘汰**：手动 `--cache-clean` + 配置 `cache.max_entries` / `cache.max_bytes` 上限，
  超限按访问时间淘汰最旧（LRU）——仅在编译入口顺带检查，无常驻后台。

## 四、详细设计

### 4.1 构建键与内容寻址

- 定义**依赖集** `D = {入口源码}` ∪ `{全部 import/using 递归可达文件}`。tiec 在语义
  `expand_imports` 已解析依赖路径与读取顺序；本重构把该依赖解析**提前复用**于键计算。
- 每个文件 `f ∈ D` 取其字节做 `tsha1r` 指纹 `fp_f = tsha.tsha1r(bytes(f), n, base)`。
- 构建键 `K = tsha1r(排序 (规范路径:fp) 序列 + 输出相关参数 + 盐)`。参数项与现状一致
  （优化档/目标/角色/shared/emit_ir/fast_math/bounds/输入/输出路径），以维持“相同输入不同
  输出不串置”语义；路径以**规范化绝对路径**加入，避免相对路径别名导致串键。
- 参数与依赖指纹均**按确定顺序**（路径字典序）拼接，保证跨调用确定、可复现。

### 4.2 依赖清单（dependency manifest）

- 缓存命中/写入时，随产物/键副作用一个**清单文件** `<键>.dep`（文本）：
  每行 `规范化路径` + ` ` + `tsha1r 指纹`，列出 `D` 全集。
- **命中校验**：除比对键外，读 `<键>.dep`，逐一复核每个依赖文件的**当前磁盘指纹 == 清单
  指纹**；任一不符（含清单缺失/损坏）判失效重编。这层校验兜底键聚合之外的任何漏网变动。
- 清单与主缓存对象同一原子命名，写入顺序：先主对象、后清单（或同目录整体原子）。

> 设计取舍：键已聚合全部输入指纹——为何还要清单复核？理由：①聚合键把“哪些输入变了”的
> 信息拍平成单一哈希，无法在命中时定位到具体越界差异；②内容寻址对象可被外部误改/清理时，
> 清单提供第二道真伪校验；③为中间级增量（§4.4）提供“哪些文件未变可复用”的粒度依据。

### 4.3 产物指纹核对 + 原子写

- **命中路径**：`file_copy(cache 对象 → 目标)` 后，对目标产物再算 `tsha1r`，与清单/对象
  登记指纹比对；不符 → 判定缓存损坏，删除该对象并重编。杜绝碰撞/残缺/篡改导致静默错产物。
- **写入路径**：先写 `objects/<fp>.tmp`，成功后 `rename` 为 `objects/<fp>`（同一文件系统内
  原子）；再写依赖清单。任何一步失败即清理残留临时文件，缓存目录始终只含完整对象。

### 4.4 分层缓存（最终产物 / IR / opt）

- 分三层粒度，按角色与 emit 模式落位：
  * **L0 最终产物**（.exe/.dll/.a/.ll）：命中直接复制即完成（现状语义，向下兼容）。
  * **L1 tieir（中端 IR）**：前端（词法→语法→语义→irgen）产物，决定多文件增量中哪些
    文件模块可复用其中间表示。
  * **L2 优化后 LLVM IR（opt）**：前端稳定 + 优化前端可拆时，复用优化结果跳过重优化。
- **增量规则**（L1/L2）：按依赖清单判定——变更传播的**边界文件**及其下游重新编译，未变
  子集命中中间缓存复用。首期先落地“整文件粒度”的 L1/L2 命中复用（命中即跳过该文件的前端/
  优化），细粒度（函数/符号级）不作为本期验收门槛（接口预留）。
- 挂号点：在 Keel 真实 pass（`keel_run_pipeline` 各 `kpass_*`）之间插入缓存读/写挂点；
  与 trm 字节码目标（`.tieir` 独立分派，不缓存）保持正交。

### 4.5 淘汰策略与配置

- 新增配置项（`tiec-cache` 配置，与 `cache.dir` 同域）：
  * `cache.max_entries`（条目上限，0=不限）；
  * `cache.max_bytes`（字节上限，0=不限）；
  * `cache.lru`（开关淘汰，默认开）。
- 淘汰触发：仅在编译入口顺带检查；任一卷过量则按**访问时间**淘汰最旧，至达标。对象访问时
  更新记录（`objects/<fp>.meta` 或目录 mtime 归一化）——**不在每次命中做写盘**，改为
  编译结束写入一次，控制 IO。
- 手动治理：新增 CLI `tiec --cache-clean`（清空缓存目录）、保留 `--no-cache`。

### 4.6 CLI 与配置项汇总

| 项 | 取值 | 说明 |
|----|------|------|
| `--no-cache` | 已存在 | 关闭编译缓存（保留） |
| `--cache-clean` | 新增 | 清空缓存目录 |
| `cache.dir` | 已存在 | 缓存目录（缺省 `~/.tiec-cache`） |
| `cache.max_entries` | 新增 | 条目上限，0=不限 |
| `cache.max_bytes` | 新增 | 字节上限，0=不限 |
| `cache.lru` | 新增 | 淘汰开关，默认开 |

## 五、排号与分期

**档位：p.9.15 编译器缓存重构（内容寻址 + 依赖感知 + 增量构建）**

- p.9.15.1 **依赖感知缓存键 + 依赖清单**：依赖集解析复用、`tsha1r` 聚合构建键、
  `.dep` 清单写读与命中复核。修复“改 import 不失效”主缺陷。验收：多文件工程改依赖 → 重编。
- p.9.15.2 **强哈希 + 产物指纹核对 + 原子写**：键换 `tsha1r`、命中产物二次指纹校验、
  临时文件 + rename 原子写、内容寻址 `objects/<fp>` 去重布局。
- p.9.15.3 **中间级增量（L1 tieir / L2 opt 分层缓存）**：kpass 挂点插入、整文件粒度命中
  复用 + 按依赖清单传播变更边界。验收：多文件工程仅改单文件 → 其余复用中间产物。
- p.9.15.4 **淘汰与配置治理**：`--cache-clean` + `cache.max_entries/max_bytes/lru`，
  超限 LRU 淘汰。验收：注入上限 → 最旧条目被逐出。
- p.9.15.5 **验收与回归**：`verify-cache.tsh.tie` 全面强化（新增依赖变更失效/篡改/指纹
  碰撞/原子写/淘汰/增量复用探针）+ 自举不动点复核 + s21/diagcodes/m5 回归不劣化 + grep
  `.ps1`=0（脚本一律 `.tsh.tie`）。

> 分期顺序原则：先正确性（.1/.2）后性能（.3）再治理（.4），每期独立可验收、可落地、
> 回归门禁放行后方进入下一期；各期可并线、无前置依赖。

## 六、验收度量

- **正确性**：依赖变更必失效（多 import 递归）；碰撞/残缺/篡改必重编（指纹核对命中）。
- **增量**：多文件工程仅改一依赖文件时，L1/L2 中间产物复用计数 > 0，纯前端/优化耗时下降。
- **确定性**：同输入同参数两次编译，键与产物指纹逐字节一致；自举不动点二次 SHA 一致。
- **治理**：注入上限后缓存收敛；`--cache-clean` 清空；无利残临时文件。
- **回归**：现有 s21 / diagcodes / m5 全量不劣化；`verify-cache` 新旧全绿。

---

## 七、兼容性与迁移

- 现 `.cache` 单文件对象：首版发布后视为史前缓存，读取**平滑容错**（新路径找不到即重编
  并写新格式），不试图转换旧格式；`--cache-clean` 可一次性清空。
- `g_cache_salt` 语义保留（输出形态变更强制整体失效），仍按需递增。
- 对外 CLI 向后兼容：`--no-cache`、`cache.dir` 原义不变；新增项全部可选、默认不改变
  既有无缓存/单次编译的行为。
