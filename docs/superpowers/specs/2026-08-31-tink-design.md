## 1. 背景与定位

tie 生态的工具协作目前依赖 PowerShell 脚本 + 命令行参数 + 临时文件（如 jcc-pack 调 tiec 做 td→zd），性能差、脆弱。**tink** 定位：

* **轻量、性能强大的应用**——生态的**互联核心**；

* **通用、语言无关**：不仅是 tie 生态内部，**任何语言的组件**（tie / Rust / C / C++ / Python…）只要遵守统一帧协议即可接入，作为通用的数据流互联服务；

* **数据流互联服务**：专注连接/路由组件间的 zd 数据流（管道化）；

* **替代 PowerShell 等命令行工具**：组件间数据以统一 IO 传递，无需脚本胶水；

* **未来 tie 命令行可基于 tink 构建**。

## 2. 核心职责

* **组件独立进程，不被 tink 承载调用**：tiec、jcc-pack 等保持独立可执行；

* **组件可为任意语言**：tie / Rust / C / C++ / Python… 只要组件进程遵守统一帧协议即可接入；

* tink 负责**启动组件 + 按管道定义把 A 组件输出路由到 B 组件输入**；

* 数据流统一为 **zd 字节 ABI**（模块.函数(字节进)→字节出，语言无关）；

* 组件 stdin/stdout 统一为 **zd 帧流协议**（长度前缀 zd 消息）。

## 3. 统一 IO 契约

* **数据载体**：zd（`.zd`，语言无关二进制，见 zd v2 设计）；

* **调用形态**：`模块.函数(字节进) → 字节出`；

* **帧协议**：组件 stdin/stdout 上以「长度前缀 + zd 消息」为帧；帧带边界与 CRC 校验（zd v2 帧边界/CRC 特性），tink 可靠路由；

* **接入门槛**：任意语言只需实现 zd 帧协议（长度前缀 + CRC）即可成为节点，不依赖 tink 内部。

## 4. 形态（同一 zd 帧协议核心）

**形态 A：管道编排器（主形态）**

* tink 按管道定义启动组件进程，把组件 A 的 zd 输出帧路由到组件 B 的 zd 输入帧；

* 示例：`tink pipe "tiec:td2zd | jcc-pack:build" > out.jcc`

* 纯流式、轻量、高性能；替代脚本 + 临时文件。

**形态 B：常驻 hub（扩展）**

* tink 常驻，组件连上注册端点，按路由表转发 zd 消息；

* 跨进程/跨语言灵活，引入 IPC/网络复杂度。

**形态 C：库式互联层（扩展）**

* tink 作为库链接进组件，组件间直接 zd 流互连（无常驻服务）。

三者共享**统一 zd 帧协议**，A 为主，B/C 按需扩展。

## 5. 应用场景

* **dp 构建**：jcc-pack 调 tiec td→zd 不再经 PowerShell——管道 `tiec:td2zd | jcc-pack:build`；

* **工具链编排**：数据转换/构建流程以 zd 帧流连接；

* **跨语言数据管道**：不同语言组件（如 Rust 工具 ↔ tie 工具 ↔ C 库进程）经 zd 帧流互通——通用互联场景；

* **未来 tie 命令行**：tiec、pkg、tiedb 等命令可基于 tink 的统一 IO 构建。

## 6. AI 相关规划

tink 作为**通用**数据流互联服务，天然承接 AI 生态（语言无关定位的直接延伸）：

* **AI 代理作为 tink 节点**：LLM / AI agent 进程经统一 zd 帧协议接入管道，作为数据流参与者（消费/产出 zd 帧）；tink 不区分节点是程序还是 AI——同一帧协议，AI 即插即用；

* **AI 工具编排**：tink 作为 AI 调用工具的统一 IO 层——工具以 tink 节点形式注册，AI 经 tink 以 zd 帧调用（类比 MCP 思路，但载体为 zd 帧流、语言无关、无框架绑定）；

* **AI 辅助开发**：tink 相关工具链（组件、管道、探针）由 AI 辅助实现/测试，tink 网络即 AI 可直接操作/验证的节点网络；

* **与 MCP 对接（后续）**：tink 节点协议与 MCP（Model Context Protocol）工具调用对接，AI 生态工具经适配器接入 tink 管道。

## 8. 错误处理

* 管道某段失败 → 定位段并报告，退出非 0；

* 帧 CRC 校验失败 → 拒绝该帧并报错（不静默传递损坏数据）；

* 组件缺帧协议支持 → 报错提示接入方式。

## 11. 非目标（YAGNI，本阶段不做）

* 不承载/嵌入组件运行（组件保持独立进程）；

* 不做任务调度/并行（仅数据流路由）；

* 不替代 tiec 编译链路本身；

* 不引入网络协议栈（hub 形态的 IPC 后续按需）。
