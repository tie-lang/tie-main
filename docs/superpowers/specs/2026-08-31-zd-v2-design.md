# zd v2 设计文档（语言无关二进制序列化格式）

* 日期：2026-08-31

* 状态：待批准

* 关联实现：`tiedb/src/zd.tie`（v1 权威）、`tie-main/tieDB/persist/zd.tie` 与 `jcc-core/core/zd.tie`（副本）

## 1. 背景与定位

zd v1 是 tie 生态的二进制数据格式（MessagePack 分区 + Protobuf varint 思路，`TIEDBZD` 魔数 + 版本 1），但存在局限：

* 实现与说明绑定 tie 语言（扩展名 `.zd.tie` 易与 tie 数据文件混淆）；

* f64 位模式用数学分解（log/pow/parse\_float 往返），编解码慢；

* 连续 `concat` 拼装 O(n²)、decode\_string 逐码点拼接 O(n²)；

* 无字符串字典、无列式编码，大批同构 record（棋子/装备/羁绊、td→zd 输出）体积冗余；

* 无扩展类型，无法携带 tie-IR 等语言特有载荷。

**zd v2 定位**：语言无关的通用二进制序列化规范，**任何语言（tie / Rust / C / C++ / Python…）可独立实现**。本设计文档即规范基准。

* **扩展名**：一律 `.zd`（废弃 `.zd.tie`，含 plugin-kernel 方案中的 `*.zd.tie` 一并改为 `.zd`）；

* **服务场景**：dp 数据包容器、Snapshot/Advice、tiec td→zd、tink 统一 IO 帧、tie 生态数据交换。

## 2. 头部与版本

```
T I E D B Z D   [d1][d2]        共 9 字节
```

* 前 7 字节 = 魔数 `TIEDBZD`；

* `d1`、`d2` = **2 位 base-48 版本数字**（各 1 字节，存数字值 0..47）；

* 字符集 = std base48：`0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKL`（'0'=0，'1'=1 … 'L'=47）；

* `version = d1*48 + d2`；**当前设计 v2 = "02" = 字节 \[0]\[2]**（无 `v` 标记，直接拼魔数后）；

* 识别规则：**9 字节且魔数匹配、d1,d2∈\[0,L]（L 即 48 进制的 47）→ v2**；**8 字节（`TIEDBZD`** **+ 0x01）→ v1**（版本缺失一律按 v1 处理）；其余非法。

v2 头后 **flags 字节固定存在**（10 字节头：魔数 7 + 版本 2 + flags 1；「可选 flags 区」落地为始终携带、缺省 0，避免与 body 歧义）：字典（bit0）、列式（bit1）、ext（bit2）、流式（bit3）、压缩变体（bit4）。

## 3. 类型系统（语言无关核心）

| 类型     | 编码                        | 说明                                   |
| ------ | ------------------------- | ------------------------------------ |
| i64    | fixint/定宽（v1 既有）          | 正 0x00-0x7f、负 0xe0-0xff、0xd0-0xd3 定宽 |
| u64    | 0xcf/0xd3 大端              | 无符号承载                                |
| f64    | 0xcb + 8 字节大端 IEEE 754    | 位模式直写（v2 用 bitcast，见 §4）             |
| bool   | 0xc2/0xc3                 | <br />                               |
| string | fixstr/str8/16/32 + UTF-8 | v2 新增字典引用形式（见 §5）                    |
| bytes  | 0xc6 类 + 长度 + 原始字节        | 二进制 blob（图标/像素/任意载荷）                 |
| array  | fixarray/16/32            | 自描述（元素带类型标签）                         |
| map    | fixmap/16/32              | 平行表键值（语言无关：键 string）                 |
| null   | 0xc0                      | 空值/缺失（v2 新增，区分缺失与空值）                 |
| ext    | 0xd7 + 类型标记 + 长度 + 载荷     | 扩展类型（MessagePack ext / CBOR tag 思路）  |

* **tie 特有类型（char/trit）与 code（tie-IR）一律走 ext 子类型**，不进核心类型系统；

* 每语言实现必须支持核心类型；ext 可选择性支持（未知 ext 类型可整体跳过）。

## 4. 性能优化

1. **字节构建器（append-only buffer）**：encode 全部写入单增缓冲（append 原语），消除连续 `concat` 的 O(n²) 重复分配；
2. **f64 bitcast 原语**：tie 语言新增 `f64↔i64` bitcast 原语（编译器 + 语言改动）；zd 用原语替代现有数学分解（`floor(log/log2)` + `pow` + `parse_float(to_string(e))`）。其他语言实现天然有 bitcast；
3. **decode\_string 批量构建**：缓冲一次解码 UTF-8，避免逐码点 `out = out + str_from_code(cp)` 的 O(n²) 拼接；
4. **预分配 + 批量原语**：builder 支持 reserve 预分配容量减 realloc；批量 encode/decode（string\_array、列式）减少每元素函数调用与类型分派；
5. **零拷贝/引用读取**：decode 字符串/bytes 支持返回「区间引用」（offset+length）而非拷贝，大 blob（图标/像素/模板）零拷贝读取；
6. **跳读/随机访问偏移表**：大数组/容器带偏移表（每 N 元素记录字节偏移），O(1) 定位 + 快速跳过；
7. **流式分块 + 压缩变体声明**：大负载分块帧（流式位）；头部/内容声明 zstd/lz4 压缩变体，读端自动解压；
8. 大端 u16/u32/u64、varint 读写原语保持 v1 既有实现。

## 5. 体积优化

1. **字符串字典/引用**：v2 容器可带**字符串池段**（语言无关：池 = 字符串表，任意语言可建）；字符串编码新增「字典引用形式」（池内索引 varint，需 flags 字典位）。重复字符串（id、羁绊名）只存一次；
2. **列式编码**：新增**列式容器**（语言无关：列 schema = 类型数组 + 各列值）；大批同构 record（棋子/装备/羁绊、td→zd 输出）按列存，去重 + 局部性 + 体积可预测。

## 6. 格式能力

1. **列式容器**（语言无关）：`列数 + 每列类型 + 每列长度 + 各列值`，供表格型数据；
2. **ext 扩展类型**：`0xd7 + 类型标记(i64) + 长度 + 载荷`；tie 的 char/trit、平台数据走此；
3. **code 类型承载 tie-IR**：ext 子类型（类型标记约定，载荷对齐 tieir\_ser 的 `TIEIR` 7 段格式：魔数/模块头/字符串池/符号表/IR 主体/导出表/span）——供 tink、插件分发内嵌 IR；
4. **null/optional**：核心 null 类型（0xc0），区分「缺失」与「空值」；
5. **schema 段**：容器携带字段名+类型 schema（语言无关），任意语言可反序列化到对象；
6. **流式帧边界 + CRC**：流式帧带长度 + CRC 校验，tink 统一 IO 帧可靠边界；
7. **内容哈希段**：容器内嵌内容哈希（tsha1x/fnv），读端完整性校验；
8. **flags 区**（§2，含压缩变体位）。

## 7. 兼容性

* **v1（8 字节）读取保持**：v2 实现必须能读 v1（含 `TIEDBZD` + 0x01 头）；

* **v2 新类型对 v1 消费者不可见**：record 字段号只追加（v1 消费者跳过未知字段）；ext 类型可整体跳过；

* 版本演进：`d1*48+d2` 单调递增，向后兼容。

## 8. 同步策略

* `tiedb/src/zd.tie`：权威实现（升级为 v2，同时保留 v1 读取）；

* `tie-main/tieDB/persist/zd.tie`、`jcc-core/core/zd.tie`：副本按权威同步；

* 其他语言实现：以本设计文档为规范基准，各自独立实现核心类型 + 头部/版本。

## 10. 非目标（YAGNI，本阶段不做）

* 压缩算法不内嵌实现（v2 仅声明压缩变体，由读端/调用方接 zstd/lz4 解压）；

* 加密/签名（数据包安全是上层策略，不在格式内）；

* 数据库/索引（属 tieDB 范畴，本格式只管序列化）；

* 内存映射 I/O（后续按需）。
