# TSHA1 内部状态随输出位长（state-per-n）设计定稿

- **日期**：2026-08-30
- **状态**：设计定稿（头脑风暴流程已获用户核准，待写实施计划）
- **范围**：std/tsha1.tie 哈希族的结构升级——**内部状态规模由输出位长参数 n 决定**，
  消除"输出扩展被内部状态封顶"（论文基准揭示：n=48/96 都止步于 256 bit 内部状态）。
  本设计为 docs/superpowers/specs/2026-08-30-tsha1-tri-quad-track-design.md 的续篇，
  变更是对 f/r/b/x 四模型共有的"状态-输出管线"的再参数化。
- **依据**：std/tsha1.tie（现行实现）、tests/tsha_probe/*（现行探针与参考生成器）、
  scripts/bench/tsha1-cmp-bench-out.txt（64KB 多 n 实测：n=48 与 n=96 均 256bit 有效位）。

## 1. 背景与目标

现行设计：内部摘要固定 32 字节（f/b/x，256 bit）或 16 字节（r，128 bit），
输出位长 n 仅是外层 base48 编码长度；n 超过内部编码容量（46 符号）后经 XOF
（fit48）从**同一个内部摘要**确定性扩展——**扩展不产生新熵**，碰撞安全被内部状态
封顶（f/b/x → 2^128 生日界、r → 2^64 生日界），n=96 与 n=48 完全等价。

本设计目标：**内部状态规模由 n 决定**，使

- 有效安全位 = min(名义位 n·log₂48，状态位) = **名义位**（对全部合法 n 成立）——
  输出多长，状态就多宽，无封顶；
- 名义碰撞界 2^(5.585n/2) 对每个 n 都可兑现：n=48→2^134、n=96→2^268、
  n=144→2^402；
- "轻量"由模型轮数（r 的 R_R=8）体现，而不是由状态宽度体现。

**不变量（本设计不触碰）**：对外主接口签名
`tsha1f/b/x/r(msg, n, base=48)`、base 集合 {2,3,8,16,48}、base48 字符集
（0-9a-zA-Z，0↔o/1↔l↔I 视觉混淆取舍）、逐字节处理、64 字节块大小、
纯零填充 + 64 位计数器 t（无 0x80/无长度位）、24 基调度键 skey 派生方式、
非法值（base/位长）拒绝语义。

**变更面**：状态规模公式、通用 W 字压缩核、常量（IV 按 W 扩展）、输出管线
（删除 XOF、不足拒绝）、API（删除 `_hex` 变体）、位长集合（新增 128、144）、
全部 KAT/探针/参考生成器/基准联动。

## 2. 状态规模公式（规格，实施只准照此执行）

记 `L48 = log2(48) = 5.5849625007`，每字 trit 数 k：

| 模型 | k（每字 trit 数）| 每字信息量 bit | W(n) 公式 |
| --- | --- | --- | --- |
| f / b / x | 32 | 32·log₂3 = 50.718 | `W = max(1, ⌈n·L48/32⌉)` |
| r | 16 | 16·log₂3 = 25.359 | `W_r = max(1, ⌈n·L48/25.359⌉)` |

- **语义**：f/b/x 每字 = (M,N) 两平面各 32 位（同现行）；r 每字 = (M,N) 两平面
  各 **16 位**（16 个 trit），位运算全在 32 位掩码下进行，但有效位宽 16；
  r 的旋转一律按 **16 位循环**（`rrp16(v,n) = rr32(v & 0xFFFF, n & 15)`）。
- **覆盖保证**：由构造 `32·W ≥ n·L48`（f/b/x）、`25.359·W_r ≥ n·L48`（r）
  恒成立 ⇒ 状态全宽可直接编码 n 个 48 进制符号，**无需 XOF**。
- **位长集合（新）**：
  `{2, 3, 4, 6, 8, 12, 16, 24, 32, 48, 64, 69, 88, 92, 96, 128, 144}`
  （原集合新增 **69、92**，用于对齐 SHA3-384/512 档，见 security-design spec §1；
  位长非法仍返回空串）。

W 示例（f/b/x / r）：n=2→1/1、8→2/2、16→3/4、24→5/6、32→6/8、48→9/11、
64→12/15、**69→13/16**、88→16/20、**92→17/21**、96→17/22、128→23/29、144→26/32。

## 3. 通用 W 字压缩核（轮数固定 + 低 W 退化）

每模型轮数与轨数组合**不变**：f 双轨 R_F=12、r 双轨 R_R=8、b 三轨 R_B=14、
x 四轨 R_X=16。状态 W 变小时按退化表；W 变大时轨道内字数按比例增长。

### 3.1 轨分配表（工作状态为 2W 个 32 位槽：2i 存 M、2i+1 存 N）

| W 区间 | 结构 | 分配规则 |
| --- | --- | --- |
| W ≥ 16 | 模型原轨数 | f/r：A=⌈W/2⌉、B=⌊W/2⌋ 字；b：A=⌈W/3⌉、B=⌈W/3⌉、C=W−A−B 字（C 内 rate=⌈C/2⌉ 字、capacity=C−rate）；x：A=⌈2W/7⌉、B=⌈2W/7⌉、C=⌈2W/7⌉、D=W−A−B−C 字（LFSR 轨） |
| 8 ≤ W < 16 | 双轨 | A=⌈W/2⌉、B=⌊W/2⌋（仿 f 的注入与耦合） |
| 4 ≤ W < 8 | 单轨环式 | 全 W 字一个闭环（无轨间耦合，有注入 + 轮常量） |
| 1 ≤ W < 4 | 直接置换 | 全 W 字环式 tadd2/tmul2/quant3，无轨道概念 |

> 现行 f/r/b/x 的固定 W（16/24/31）全部落在"W ≥ 16 原轨数"分支；
> 轨道内锚点/注入/耦合均为**相对索引**（见 3.2），与 W 无关，仅整体平移。

### 3.2 通用轮步（轨 T、长度 L、轮 r、轨锚 a0）

- **注入**：轨首字 a0 吸收消息平面 `tadd2(v[2a0], v[2a0+1], rrp(M, sh), rrp(N, sh))`；
  f/r：轨 A 注入 M0/N0、轨 B 注入 M1/N1；b：轨 A 与轨 B 同上（海绵 rate 按 3.3）；
  x：轨 A/B/C 与 b 同，另 LFSR 轨（D）按 3.4。
- **轨内扩散**：对 k = 0..L−1 环式（下标 mod L）：
  `(sm, sn) = tadd2(v[2k], v[2k+1], rrp(v[2((k+2)%L)], wA), rrp(v[2((k+3)%L)+1], wA))`；
  隔对乘积 `tmul2(k, k+2)`、`quant3` 多数门取前三；结果写回（位遮挡 32 位）。
- **轮常量注入**：沿用各模型 RCON（16 字不变），错位量由 r 与 L 派生；
  b 的海绵轨常量、x 的 LFSR 常量改由相对索引注入。
- **末块折回**（r=last 之后，i = 0..W−1）：
  `h[i] ^= v[2i] ^ rrp(v[2i+1], (i*3)&31)`（b/x 再并入海绵 rate 项与 LFSR 项，
  相对索引化：`i&3`、`i&7` 之类掩码改为对 C/D 长度的取模）。
- **终筛**：fin_synth（f/r/b）与 fin_synth_x（x）推广为 **W 字版**
  （S=4 收束轮的"全 W 字环式平衡加 + 乘积 + majority"；x 四轨投影折叠 → W 字链值）。

### 3.3 海绵轨（b）相对索引规则（W ≥ 16 分支）

rate = C 首 ⌈C/2⌉ 字、capacity = 剩余；吸收目标 = rate 首 2 字；
8 字环式置换改为"rate+capacity 全 C 字环式"（窗口模式同 3.2）；
与轨 A/B 双向耦合取固定相对位（rate[0]↔A[0]、rate[1]↔B[0]、capacity[0]↔A[1]、
capacity[1]↔B[1]）；末块 rate 高位翻转 `v[l] ^= 0xFFFFFFFF`（l = rate 末字）与
capacity 折回链值保留。

### 3.4 LFSR 轨（x）相对索引规则

状态 = v[D 字]（各 32 位）；反馈 `fb = (d[3]>>16) ^ d[1]` 推广为
`fb = (d[D-1]>>16) ^ d[1]`；吸收用 M0/N0 平面；quant3 门控取轨 A/B 的长位
（相对锚）；与轨 A/B 耦合 D 个字与 A[0..D-1] 逐对平衡混；常量注入 `tsha_xdcon`
（16 字，错位量相对 D）。

## 4. 常量扩展

- IV：各模型现有种子流（SEED_F/R/B/X）**继续按计数器流取前 W 个字**；
  现行 8 字为其特例（W=8）。RCON/bscon/xdcon 仍 16 字（轮数固定 ≤16），值不变。
- r 的常量取数后与 16-trit 语义对齐：仅取低 16 位有效（高 16 位清零），
  保证与生成器一致。
- 复现性注记不改：`SHA-256(SEED ‖ u64be(k))` 计数器流照旧。

## 5. 输出管线（删除 XOF，不足拒绝）

- **fit48 移除**（不再存在 XOF 循环）。新管线：状态全宽（32·W bit 或 25.36·W_r bit）
  → 按 base 编码 → 截断 n 符号。
- base=48：状态全宽 → hex 中间串（每字 8 位 hex 拼接）→ `b48.encode` → 取前 n 符号
  （构造保证长度充足）。
- base∈{2,3,8,16}：所需字节 `b0 = ⌊n·L48/8⌋`；状态 hex 池长度 `≥ 2·b0` 时直接
  编码截断；**不足（仅当状态字节 < b0，正常不应发生）→ 返回空串（拒绝）**。
- 非法 base / 非法位长 → 返回空串（语义同现行）。

## 6. API 变更

- 主接口不变：`tsha1f/b/x/r(msg, n, base=48)`，n 决定内部状态规模。
- **删除全部 `_hex` 变体**：`tsha1f_hex / tsha1b_hex / tsha1x_hex / tsha1r_hex`
  移除；需要 hex 输出用 `base=16`。
- 探针/调用方相应迁移（删除 `_hex` 断言；`_hex` 向量改 base16 断言）。
