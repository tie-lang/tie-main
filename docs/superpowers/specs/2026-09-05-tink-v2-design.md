## 1. 背景与动机

v1 帧协议（`std/tink.tie`）已落地且 26+ 语言库同步。本次更新基于四个方向的明确诉求（A/B/C/D）：

* **A 帧层性能**：现实现逐字节 `table_push` 构建、反射式逐位 CRC32、逐字节拷贝解析——性能余量未榨干，违反「性能优先、无 O(n²) 残留」纪律的边界情况存在；

* **B 帧格式演进**：v1 帧头无可扩展性（无版本/magic/flags），一旦协议演进无法区分新旧帧；载荷上限 4GiB，无大载荷分块；

* **C tsha1 接入**：CRC32 仅防误码（32 位、非密码学）；tie 自有 tsha1 族（4 模型 × 位长集，state-per-n 无容量缺口）可承担帧级强校验、内容寻址指纹与 P2P 节点/DHT 寻址；

* **D 语义层与 P2P 对齐**：v1 ABI 为裸 `模块.函数(字节进)→字节出`，无调用信封；D-3 去中心 P2P 需要可靠传输（序号/确认/重传）、加密（x25519+AEAD）、流式语义——tink v2 帧协议直接复用作 P2P 消息帧线格式。

## 2. 设计目标

* 语言无关：字节布局固定，任何语言实现同一协议即接入；

* 向前兼容可演进：magic + 版本 + flags + 扩展头，旧实现可识别新帧并拒绝/降级；

* 校验可选可分级：CRC32 快路径默认、tsha1 强校验可选；

* 大载荷可分块：4GiB 上限化解为任意大流；

* 性能优先：头固定大小快路径、批量构建、查表 CRC、零拷贝引用读，无 O(n²)；

* 与 D-3 P2P 共享：加密位、流式语义、寻址（tsha1）直接服务去中心 P2P。

## 3. 帧 v2 线格式

```
帧 = [ magic: u8[2] ][ version: u8 ][ flags: u8 ][ len: u32 BE ][ ext_len: u16 BE ]
     [ ext: ext_len 字节 ][ payload: len 字节 ][ integrity: 定长 ]
```

| 段         | 长度          | 说明                                   |
| --------- | ----------- | ------------------------------------ |
| magic     | 2 字节        | 固定 `0x74 0x6B`（"tk"），识别帧族，避免与任意字节流混淆 |
| version   | 1 字节        | 帧格式版本，当前 = 2                         |
| flags     | 1 字节        | 位掩码，见 §3.1                           |
| len       | 4 字节（BE）    | payload 字节数（不含头/扩展头/校验）              |
| ext\_len  | 2 字节（BE）    | 扩展头字节数（TLV 序列，默认 0）                  |
| ext       | ext\_len 字节 | TLV 序列（§3.2）                         |
| payload   | len 字节      | 载荷（zd 字节流）                           |
| integrity | 定长（去 flags） | §3.3                                 |

### 3.1 flags 位定义

| 位    | 名称          | 含义                                         |
| ---- | ----------- | ------------------------------------------ |
| 0    | INTEGRITY   | 校验模式：0 = CRC32（默认快路径），1 = tsha1（模型/位长见扩展头） |
| 1    | COMPRESSED  | 载荷已压缩（压缩算法见扩展头）                            |
| 2    | ENCRYPTED   | 载荷已加密（AEAD 算法与 nonce 见扩展头）                 |
| 3    | STREAM      | 分块流帧（会话与序号见扩展头 §3.4）                       |
| 4    | STREAM\_END | 分块流末帧                                      |
| 5..7 | 保留          | 必须为 0                                      |

### 3.2 扩展头 TLV

扩展头是 `key: u16 BE + value_len: u16 BE + value` 的 TLV 序列，总长 = ext\_len。未知 key 的实现**必须跳过**（按 value\_len 前进），保证前向兼容。

| key | 名称              | value 内容                        |
| --- | --------------- | ------------------------------- |
| 1   | TSHA1\_MODEL    | 1 字节：f/r/b/x（0/1/2/3）           |
| 2   | TSHA1\_BITS     | 1 字节：位长集合 {2..144}              |
| 3   | COMPRESS\_ALGO  | 1 字节：0 = zstd，其余保留              |
| 4   | ENC\_ALGO       | 4 字节：AEAD 算法 ID + nonce 前缀      |
| 5   | STREAM\_SESSION | 4 字节（BE）：会话 ID                  |
| 6   | STREAM\_SEQ     | 8 字节（BE）：序号                     |
| 7   | STREAM\_TOTAL   | 8 字节（BE）：整流载荷总字节（首帧）            |
| 8   | TIMESTAMP       | 8 字节（BE）：Unix 毫秒，可选             |
| 9   | EXT\_META       | 任意附加元数据（key-value 嵌套，JSON/zd 表） |

### 3.3 校验段

| flags INTEGRITY | 校验值长度 | 算法                                        |
| --------------- | ----- | ----------------------------------------- |
| 0（默认）           | 4 字节  | CRC32-IEEE（同 v1，多项式 0xEDB88320）           |
| 1               | 32 字节 | tsha1（模型/位长默认 f/n=48），取 digest 状态池前 32 字节 |

tsha1 校验规则：按扩展头 TSHA1\_MODEL/TSHA1\_BITS（缺省 f/n=48）计算 `tsha1f(payload, n)` 的 hex digest，转字节后**取前 32 字节**为校验值；状态池不足 32 字节（正常不应发生）视为生成错误。实现应缓存按 (model,n) 确定的 32 字节截断规则，跨语言一致。

### 3.4 分块流

大载荷按 CHUNK 大小（建议 64 KiB）拆分：

* 首帧：flags.STREAM=1，扩展头含 STREAM\_SESSION（新会话 ID）与 STREAM\_TOTAL；

* 中间帧：flags.STREAM=1，扩展头含 SESSION + 递增 STREAM\_SEQ；

* 末帧：flags.STREAM=1 | STREAM\_END=1。

接收端按 SESSION 重组；SEQ 缺失/乱序由 D 层可靠性处理（§7）。分块流允许 payload 单帧不超过 64 KiB，突破 4GiB 上限并降低单缓冲区压力。

## 4. A 组：帧层性能

* **批量构建**：`frame_encode` 改为两段式——先算头（固定 8/10 字节）再整体拼接，禁止逐字节 `table_push`；各语言库提供「构建器」一次性产出；

* **查表 CRC32**：CRC32 反射式逐位 → slice-by-8 查表（表 8×256）；小载荷（≤64 字节）仍走逐字节快路径避免查表开销；

* **零拷贝引用**：`frame_next` 解析成功后返回载荷的**引用视图**而非逐字节拷贝（大帧零拷贝）；`frame_skip` 保持零拷贝；

* **分级校验**：默认快路径仅校验头（len < 4GiB、magic/version 匹配）即交付，完整 CRC/tsha1 校验由上层按需开启（管道可靠路由开启，纯流式转发可关）。

性能约束：所有实现禁止逐字节字符串拼接（`x = x + c`）与逐字节表 push 于热路径。

## 5. B 组：兼容与演进

* **v1 识别**：v1 帧无 magic（首 4 字节即 len）——v2 接收端对无 magic 的首 16 字节流按 v1 解析（向后兼容读），新帧一律写 v2；

* **版本协商**：version 字段递增；未知版本 → 拒绝该帧并报告「帧版本不支持」；

* **flags 未知位**：置位但实现不识别 → 对该帧按「不可信」处理（拒绝或交由上层，实现自定义策略并在探针覆盖）；

* **ext TLV**：未知 key 跳过（§3.2），保证老实现读新帧不崩。

## 6. C 组：tsha1 应用

| 应用        | 规则                                                | 默认参数   |
| --------- | ------------------------------------------------- | ------ |
| 帧级强校验     | flags.INTEGRITY=1，§3.3 截断规则                       | f/n=48 |
| 内容寻址指纹    | `content_id = tsha1f(zd_bytes, n)`（文件/消息级别，重合成校验） | f/n=48 |
| P2P 节点 ID | `peer_id = tsha1f(ed25519 公钥字节, n)`               | f/n=48 |
| DHT 键     | `dht_key = tsha1f(名字/内容, n)`，XOR 距离用 hex 字节序比较    | f/n=48 |

对齐基础：n=48 档位 ≈ 256bit 输出（对齐 SHA3-256），缺省一致；具体模型/位长可按场景在扩展头覆盖（帧）或约定（寻址）。

## 7. D 组：语义层与 P2P 对齐

* **zrpc 信封（可选类型帧）**：以 EXT\_META 携带调用契约——`req_id: u64`、`error_code: u16`、`stream_id: u32`、`op`；支撑请求/响应匹配、错误回传、流式与双向调用，为形态 B（hub）铺路；

* **可靠性（P2P）**：STREAM\_SEQ + ACK 帧（type 帧）实现序号确认与超时重传；STREAM\_TOTAL 支持进度检测；

* **加密（P2P）**：flags.ENCRYPTED + ENC\_ALGO——用 tie std 现有 x25519（密钥协商）+ AEAD（ascon\_mac/poly1305 组合或预置 AES-GCM 常量）加密载荷，nonce 前缀入扩展头；

* **心跳（hub/P2P 保活）**：type 控制帧 ping/pong + TIMESTAMP；

* **寻址（P2P）**：peer\_id/dht\_key 用 §6 规则，为 D-3 去中心 P2P（打洞直连 + DHT 发现）提供统一身份与建键。

## 8. 跨语言实现约定

* 同一字节布局与默认参数（§3/§6），校验向量一致；

* CRC32 向量：`crc32("123456789") == 0xCBF43926`（v1 沿用）；

* tsha1 校验向量：`tsha1f("", 48)` 与 `tsha1f("123456789", 48)` 的 32 字节截断值作为 tink v2 跨语言 KAT（由 tie 侧 `std/tsha1` 先行固化，多语言实现依据同一源值）；

* 各语言 tink 库（tink-c/rust/python/aardio 等）同步 v2，保留 v1 读取路径。

## 9. 探针与验收

| 探针             | 覆盖点                             |
| -------------- | ------------------------------- |
| 帧 v2 编解码往返     | encode→parse 一致，flags/ext 全字段保留 |
| CRC32 快路径      | 默认帧校验通过/损坏帧拒绝                   |
| tsha1 强校验      | f/n=48 校验通过/篡改载荷拒绝（跨语言同一 KAT）   |
| 扩展头未知 key 跳过   | 老实现读新帧不崩                        |
| 分块流重组          | 3 块拆→重组成整载荷一致，乱序/丢帧报告           |
| v1 兼容读         | v1 帧可被 v2 实现解析（向后兼容路径）          |
| 性能（无 O(n²)）    | 10MiB 载荷编解码耗时线性（基准比对记录）         |
| 加密握手（后续接入 P2P） | x25519 协商 + AEAD 往返一致           |

## 11. 非目标

* 不承载/嵌入组件运行（沿 v1，组件独立进程）；

* 不含 P2P 完整栈（打洞/DHT/relay 属独立设计，本协议仅为其帧与寻址基础）；

* 不替代 tiec 编译链路本身。
